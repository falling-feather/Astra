## 0. 全局总览与硬规则

星序面向单校使用：管理端由学校管理，教师制作与组织教学，学生按授权学习。本校实例保留系统预设资源，不建设跨校公共平台或跨校资源交流。

“系统资源”与“教师授课课程”是不同对象。系统资源可以在登录后自由探索；教师发布到学校资源库的课程，未加入的学生只能看介绍，加入后才能读取正文。资源可重复引用，课程、教学分叉和学生记录仍有各自的身份。

教师修订公共内容时，只同步到本人名下、具有明确同源关系且确有相应内容的课程。学校既可一次批复，也可逐门管理。审核通过不等于已经发布；教师只能发布学校审过的快照。旧学习记录与成绩保留，是否补做由教师明确选择。

本轮实验端交付扩课与统一改进计划，不以少数精品课程或 3D 代表实验为实施主线。管理平台的教师、学校和学生页面属于后端业务闭环的必要交付，不以仅有 API 代替可操作流程。

## 1. 当前基线与交付目标

### 1.1 已有事实

现有系统具备三角色、学校与班级、教师申请、建课审核与选课、多人共享草稿、不可变发布、三种完成预设、学习证据和工作台。正式目录为 `90 / 18 / 19 = 127` 个活动身份；它不是新分叉课程的数量，也不代表所有活动具备相同记录能力。

当前仅有 `/api` 与 `/api/v1` 主业务入口；课程信息审核与教师内容发布分离。课程家族、跨分叉同步、逐候选内容审核和本文所列 `/api/v2` 尚未实现。不能把已存在的内容版本或页面预演等同于本计划的新版本管理系统。

上一轮审查与工作区修正的真实结果见 [03 工作区交付与规划归档](03-发布历史.md#6-规划替换与工作区交付归档)。`ARCH-011 / BE-031 / BE-032` 的范围和验证已迁出活动任务区，不作为本轮研发已完成的证据。

### 1.2 本轮研发完成后的可观察结果

1. 教师能从系统资源、已发布且有权取用的校内课程或空白模板建立自己的课程，配置讲解、题目及开放的互动设置。
2. 同一套内容可以派生为高一版、高二版等并行课程，各有名称、编号、设置、学生关系与发布历史。
3. 教师一次提交公共内容修订，学校能看到来源课程、影响版本和逐项差异，并批量或逐门处理。
4. 教师发布已通过的候选后，学生按所属课程和版本学习；历史成绩、补做和旧结果认定都可追溯。
5. 资源目录、课程查询、统计、后台任务与故障诊断形成一致的后端服务；必要页面能操作完整流程。
6. 实验端形成按课程覆盖、前置关系和共用品质标准组织的扩展与修改清单。

## 2. 完整实施方案

### 2.1 术语、身份与模型边界

| 对象 | 目标职责 | 身份与约束 |
| --- | --- | --- |
| 系统资源 / 资源版本 | 本校实例预置的学习内容、来源、运行引用与能力说明 | 保留稳定资源键；新版本不覆盖旧版本；教师不能写入系统原件 |
| 模板 / 模板版本 | 可编辑字段、参数、渲染方式、验证和记录能力 | 参数受模板约束，运行代码与配置分离 |
| 课程家族 | 表达有证据的共同来源 | 由取用或派生过程建立，不按标题、学科或相似正文猜测 |
| 教学分叉 | 面向不同教学对象的独立课程 | 以课程 ID 区分，昵称和学科用于展示与分类；高一版、高二版各有名单 |
| 单元 / 内容块实例 | 一门课内的具体学习安排 | 实例 ID 与资源来源 ID 分离；重复引用同一实验不会共用完成结果 |
| 草稿 / 候选修订 | 可编辑工作内容与送审快照 | 草稿有并发代际；候选冻结内容、设置、资源引用和补做策略 |
| 修改批次 / 审核项 | 一次提交与每门受影响课程的审核结果 | 一个批次有多个审核项，审核状态以各项为准 |
| 发布包 | 实际对学生生效的课程版本 | 绑定已通过候选和完整版本依据，追加产生，不原位改写 |
| 学习尝试 / 评分历史 / 结果认定 | 行为、答案、评价与版本之间的来源关系 | 补做产生新尝试，历史不覆盖；认定引用既有结果并保存依据 |

现有 `Course` 作为教学分叉的迁移起点，增加谱系和版本关系；不把“高二版”仅做成高一课程页面的一个名称开关。课程内的修订序号与教学分叉编号分别展示。

新接口明确使用课程、单元、发布版本与学习上下文。旧 `course_cohort` 由兼容服务解析；自主探索不创建虚假班级。新旧存储之间有明确映射，不建立两份长期并行的完成真值。目标关系图见 [01 第 13.2—13.3 节](01-开发者手册.md#132-系统资源模板与课程分叉关系)。

### 2.2 系统资源、模板与教师创作

接入现有资源目录，记录标题、学科、来源、适用信息、内容版本、运行入口及真实支持的配置和记录能力。保留既有稳定键与必要兼容路由，模板和教师分叉不混入“127 项系统活动”的历史计数。

教师可以取用、重组资源或从空白模板开始，保留原作者和来源信息。初期复用现有导入、讲解、学习任务、媒体、活动引用、检查点与来源块，并补齐函数参数图像、数据图表两类基础配置模板，服务多门课程的制作。

模板编辑采用表单与即时预览。只开放模板声明的公式、参数、图表和情境；不开放任意脚本执行或自由拼装交互规则。可计算公式通过受控表达式解析与白名单运算求值，前后端使用一致的表达语义；未知字段、非法公式、缺失资源和越界配置明确拒绝。

资源能力必须如实展示。旧实验没有可靠操作记录能力时，教师采用检查点或作业作为完成方式，不能发布“会自动记录操作完成”的虚假配置。新增模板保留版本化运行制品；无法补齐的旧运行环境标为兼容模式，不宣称已经恢复全部历史渲染字节。

### 2.3 教学分叉与独立草稿

从同源课程取用或派生时，新建独立课程 ID、单元和内容块实例，保留家族与来源关系。派生不复制学生名单、提交、成绩、积分或正式完成状态；老师重新配置授课对象与准入条件。

每个分叉有自己的昵称、设置、草稿和发布历史。单元顺序、增删、年级设置等允许不同。同一课程的共同教师继续共享草稿，通过版本条件处理并发编辑；不能用最后一次保存静默覆盖他人的修改。

直接从空白模板建立的课程默认独立。仅有相同模板、标题或学科不足以判定同源；没有证据的旧课程也不自动合并到一个家族。

### 2.4 公共内容同步与冲突处理

教师选中“同步其他版本”后，先由后端形成只读预览，不能立即改变其他课程或学生正在使用的发布包：

1. 校验发起人拥有源课程，按同校、本人名下、同源关系筛选可同步目标；共同教师的单课编辑权不自动成为跨课同步权。
2. 计算本次编辑前后的实际差异，按内容来源 ID 匹配目标实例，不能按标题或数组下标替换。
3. 只传播已有公共内容的允许字段。课程昵称、授课对象、名单、章节选择、增删和排序不自动传播。
4. 没有相应内容时标记“无对应内容，跳过”，不补插章节；目标已经具有新值时标记“无需修改”。
5. 目标仍是本次修改前值时可同步；目标已有不同修改时标记冲突，教师在预览中选择保留或替换，不默认覆盖。
6. 预览按课程列出修改、跳过、冲突和学习结果影响。教师确认后，一次提交生成修改批次及各课程的候选快照。
7. 提交时重新检查源、目标代际与归属。预览过期、权限变化或未处理冲突必须返回明确结果，不悄悄部分应用。

**标准场景**：高一数学包含向量、三角、复数，高二数学包含复数、微积分。修正高一版复数与三角的公式时，高二版只预览复数的对应修改，不新增三角内容；另一位教师的课程不参与同步。

同步流程和分支判断见 [01 第 13.4 节](01-开发者手册.md#134-跨分叉同步与冲突判定)。

### 2.5 学校审核：批量操作与逐门结果

审核工作台展示修改来源、源版本、受影响课程、具体内容差异、配置差异与补做策略。管理员可选择一批审核项统一通过或退回，也可展开逐门处理。

每门课程独立记录审核结论、审核人、意见与时间；批次状态由条目聚合，不强迫所有课程取得相同结论。高一通过、高二退回时，允许高一进入发布准备，高二继续使用旧版。

送审候选不可修改。教师可以继续编辑后续草稿，但同一课程同时只允许一个待审候选；需要替换待审内容时，先撤回再提交。已有待审目标必须在同步预览中明确处理，不隐式叠加新的审核请求。

审核写入检查条目状态与版本条件。一次批量操作的选中范围保持事务一致；过期或不合法的请求不留下不明的部分审核结果。管理员随后仍可针对各项分别操作。权限按学校和实际角色校验，不能由客户端自行声明“已审核”。

### 2.6 教师发布、回滚与版本生效

教师仅能发布已通过的候选快照，不能发布审核后又改动的草稿。发布前重验权限、当前发布基础、资源有效性及候选完整性。

可一次发布选中的已通过课程；该次选中集合在事务内完成发布包、规则、绑定、审计和后台任务入队，失败整体回滚。其他未选课程和被退回课程保持各自现状。重复发布请求按幂等标识回读既有回执，不生成重复发布包或任务。

发布后，后续进入课程的学生读取新版本。已开始的尝试按注册时的版本收尾，结果按新版本认定策略决定是否计入当前状态；失去课程权限后不能继续写入。

回滚从历史版本建立新修订，重新审核后发布。历史编号、发布内容、审核意见与学生记录均不覆盖。旧的直接发布或回滚写入口同样接入新检查，不能借兼容接口绕过学校审核。状态与时序见 [01 第 13.5—13.6 节](01-开发者手册.md#135-审核项与发布状态)。

### 2.7 学习上下文、成绩留档与补做

学习上下文分为系统自主探索、正式授课学习、教师预览。身份、课程范围和版本由服务端确认；学生自报动作、服务端判分、教师评价分别记录来源。教师预览不计入学生结果，自主探索不自动折算为某门教师课程的成绩。

| 变化或场景 | 目标处理 |
| --- | --- |
| 纯展示性修改 | 默认沿用旧结果，保留原始依据 |
| 题目、完成要求或影响学习行为的配置变化 | 预览列出影响，由教师明确选择沿用或补做；选择随候选快照送审 |
| 同课其他单元发生变化 | 不能仅因课程整体规则换版就让未受影响单元失去完成状态 |
| 学生补做或教师重新评分 | 建立新尝试与评分历史，不覆盖旧提交和旧分数 |
| 新版认定旧结果 | 追加认定记录，指向旧结果、目标版本、策略和责任人；不改写旧事实 |
| 当前版本成绩与进度 | 只引用本版有效或明确认可的结果，与历史版本分开回看 |
| 重复请求、重放或任务重试 | 不能重复提交、认定、计分或发放积分 |

不把已有 `transferred` 状态改成“跨版本继承”的新含义。完成、正确性、教师反馈和掌握判断分别表达；不能因访问页面或任意客户端声明就产生权威成绩。

统一成绩、完成投影与积分计算入口，保留原有账本的可追溯性。版本绑定与认定图见 [01 第 13.7 节](01-开发者手册.md#137-学生访问版本绑定与结果认定)。

### 2.8 两种学习入口与权限

| 内容或操作 | 学生 | 教师 | 学校管理员 |
| --- | --- | --- | --- |
| 系统预设资源 | 登录后可自由探索 | 可取用、按模板制作自己的课程 | 维护本校系统资源入口与配置治理 |
| 已发布校本课程介绍 | 可查看；符合条件时申请加入 | 在授权范围查看、取用或派生 | 查看与管理本校课程 |
| 校本课程正文与历史版本 | 加入且具有有效权限后读取 | 自己或获授权协作的课程可编辑；取用不等于修改他人原件 | 为本校审核与治理读取 |
| 草稿与送审候选 | 不可读取 | 根据归属、协作权和候选状态操作 | 为审核读取，不能替教师绕过发布步骤 |
| 跨分叉同步 | 不可发起 | 仅本人名下的源与目标课程 | 审核影响结果，不能伪造教师发起身份 |
| 学习记录与成绩 | 仅本人及授权范围 | 仅自己有教学权限的范围 | 本校有明确管理目的的授权范围 |

小红未加入小明老师的高二数学课时，只能查看介绍，不能通过正文、版本、启动接口或缓存绕过准入。课程权限失败时，页面不能悄悄换成系统实验并继续显示教师课程身份。

### 2.9 目标接口与兼容方式

以下为待实现的接口分组，不代表当前已经提供。新增完整能力统一进入 `/api/v2`；身份与权限仍复用现有会话基础。

| 接口组 | 最低能力与输入输出要求 |
| --- | --- |
| 资源与模板 | 分页目录、资源/模板版本、允许配置、校验与预览；返回真实能力和来源 |
| 课程创作 | 新建、取用、派生、草稿读写；区分课程 ID、修订代际、资源来源和实例 ID |
| 修改批次 | 同步预览、一次提交、逐项/批量审核、候选回读；返回修改、跳过、冲突和意见 |
| 发布与历史 | 发布选中的已通过候选、发布回执、分页版本摘要和单版本详情、回滚修订 |
| 学习 | 启动上下文、尝试、过程记录、结果、补做、旧结果认定与历史回读 |
| 管理与建议 | 校内检索、审核待办、通知、统计、导出任务、课程关联与解释性建议 |

写请求携带版本条件与幂等标识；身份、归属、来源与审核状态由服务端维护。冲突、拒绝、未知写入结果和可重读回执使用稳定错误/结果语义，前端显示明确中文操作结果。

现有 `/api`、`/api/v1` 保留适用的兼容读取，不能产生第二套业务真值。旧客户端不能表达新能力时明确提示升级，不返回缺失正文、丢失参数或伪造成功。新旧发布写入口均由同一审批与事务服务约束。

### 2.10 分层、统计、关联建议与后台任务

后端按身份与组织、资源模板、课程创作、分叉同步、审核发布、学习评价、查询统计、后台任务与审计划分职责。HTTP 适配不继续堆入统计和持久化细节；模型字段归属明确，兼容只通过显式适配。

统计统一人群、学校/课程范围、时间与发布版本。发布历史改为分页摘要，选中后才取正文；课程汇总使用批量查询，清除逐课程重复读取。复用请求编号和耗时记录，贯通修改批次、审核项、发布和任务，能够定位慢查询与失败来源。

课程关联区分必需先修、推荐先学和相关拓展，校验循环关系与失效引用。自主探索只提供建议；正式课程先修限制由教师明确配置。建议根据有效事实输出下一步和原因，不自动选课、改分或虚构掌握程度。实验端的学习网络展示按扩课计划后续推进。

复用现有 DB-backed worker 支持站内通知、汇总重算和导出。业务写入与任务入队一致，执行有重试、幂等、失败诊断和权限复验。外部投递通道不因增加站内任务而自动开启。

### 2.11 渐进迁移与维护边界

以现有工作区为起点，先建立对象映射与迁移校验，再逐步接入新服务和页面。保留旧身份、真实发布、学习记录和上一轮修正，不通过重置数据获得干净的新模型。

能够核实的来源才补入谱系；未知的旧课程保持独立。历史发布保留其当时身份，不能补写虚假的学校审核记录。未完整迁移的旧能力明确使用兼容读取，不扩大可见范围或绕过新发布要求。

采用有目标映射的 Alembic 迁移，验证空库、已有数据、升级、回退与再次升级。先使读取和旧数据映射成立，再切换创作、审核发布及学习写入；移除旧通道前完成消费者与回归迁移。

### 2.12 实验端课程拓展与统一改进计划

本轮对实验端交付初步计划，内容实施依后续任务推进。规划按学科盘点现有课程的覆盖、重复、前置关系、互动与解释缺口；课程编号、数量和标题以实际目录核对，不把教学分叉重复算成新增系统实验。

数学优先补充启发性、趣味性与生活决策方向。下表是候选规划主题，尚未新增为正式课程，也不承诺每个主题对应一个新运行器。

| 候选方向 | 学习组织重点 | 与既有内容的连接 / 复用检查 |
| --- | --- | --- |
| 入门博弈论 | 选择、收益、合作与竞争，逐步建立策略直觉 | 评估与概率、表格、参数图表模板的连接 |
| 随机现象与模拟 | 随机漫步、抽样与多次观察的差异 | 优先复用概率统计的观测与图表能力 |
| 优化与决策 | 约束、目标与方案取舍 | 对照不等式、导数应用、建模内容，避免重复命名 |
| 网络与数学结构 | 关系、路径与结构的可视化理解 | 对照现有算法图实验，优先跨学科组织与解释复用 |
| 迭代与规律探索 | 简单规则产生的变化与图形 | 对照数列、函数、建模内容，明确真正新增的观察价值 |

每项候选必须记录目标对象、学习目标、建议前置、后续关联、互动形式、解释方式、模板复用、工作量与验收方式。下一轮扩充顺序依据覆盖缺口和复用收益，不以少数精品课程提高个别深度。

共同质量基线包括：观察对象清楚、交互真实有效、参数和结果可解释、失败有反馈、模型边界有依据、键盘/触控和移动 Web 可用。课程难度可以递进，讲解与交互品质保持共同标准。既有课程按共性问题成组改进，3D 作为后续适用内容的可复用表达能力评估。

### 2.13 正式门户接入与部署约定

本阶段沿用已确认的 Three.js 星云、透明导航和透视多轨课程轮盘，补齐教师课程、班级、作业批改与学生提交/反馈；必要管理员审核与同一套数据衔接。原工科实验室、代码空间和未来星系的实际页面保留，不以重新制作少数深度课程代替本轮接入。

- `qianduan/` 成为正式前端源码入口；页面、请求、数据派生与三维渲染分开。后端仍以 FastAPI 为业务权威，前端不能通过页面状态自行宣布完成或生成真实分数。
- 用户已确认 **GitHub Pages 静态演示 + 本机真实前后端联调**。演示明确标识并仅使用合成数据；真实请求失败不能返回演示成功。两种产物分别输出，防止部署串用。
- `main` 保存完整源码；`qianduan` 保存从已提交源码生成的独立静态制品。发布脚本核对来源和分支占用，不切换或清空主工作区。
- 教师资料与内容沿用现有 v1 工作流，不补造旧资源课程的审核、谱系、发布和成绩。跨课程家族、候选内容审核与补做迁移仍属于下面未实施的任务。
- 桌面操作、权限正反向、版本冲突与失败反馈优先。按用户要求不扩展手机端精调，也不接入小程序或公网业务后端。

### 2.14 交叉审查后的课程改进顺序

当前活动身份数为 127，数量不是课程质量结论。每轮新内容须同时检查覆盖、前置关系、交互、解释、模型边界及学习评价，不能只检查画面。详细实现现状与技术缺口见 [01 当前完成边界](01-开发者手册.md#10-当前完成边界)；下表是后续设计约束，不是已完成课程。

| 维度 | 本次确认的缺口 | 下一轮处理与验收 |
| --- | --- | --- |
| 广度 | 数学的函数/高中主线较密，策略选择、随机过程和关系结构直觉较少 | 先设计博弈与合作、随机漫步与抽样、网络与路径三组启发活动；逐组核对既有概率/图算法内容，避免同义扩数 |
| 递进 | 单项实验多数可独立打开，跨课建议不等于经过设计的学习路径 | CONTENT-011 先登记每项的必要前置、可选拓展和下一步；为新手、已有基础者提供不同入口，不用年级硬推断掌握程度 |
| 交互 | 代码空间有预测—运行—追踪—修正框架，普通实验的记录能力不一致 | 公共改进先统一“预测、改变一个变量、比较结果、解释原因”；不能把点击或停留时长当作完成 |
| 深度 | 127 个身份的模型复杂度和讲解完整度不同；工程三条旧 slug 仍共享桥梁实现 | 保持共同的解释与反馈底线，在目录声明实际模型与共用关系；提高整组质量后再增加难度，不优先打造单门精品 |
| 表现 | 已有 Canvas、DOM 和 Three.js 表达，3D 未必对每项内容都有收益 | 3D 优先用于空间关系、遮挡和视角确有教学价值的模板；Blender 资产与数值求解分离，不以精细美术替代可解释模型 |
| 适配 | 参数、说明和评价规则还没有统一的可配置模板 | BE-033 与 FE-046 先实现受控公式图像和数据图表模板；同一模板支持不同情境与讲解，配置越界要拒绝 |
| 评价 | 当前发布、检查点和作业可运行；跨版本补做与旧结果认定仍未实现 | DATA-011、BE-037、BE-038 明确旧尝试、当前认定和教师补做决策；沿用、补做、换版与重复请求都须有可追溯结果 |
| 内容资源 | 媒体块已有结构元数据，缺少完整素材文件服务与版本化读取链路 | 随资源版本任务补齐素材登记、可用性、授权、来源和版本固定；资源缺失不得以空白图或假播放器通过验收 |

课程扩展以一组相互衔接的活动为单位交付，每组都能复用同一套编辑、解释与评价工具。目录和后台中的活动、授课课程、单元实例分别计数；不得把复制界面、修改标题或新增旧 slug 算成独立高质量课程。

## 5. 验收与性能目标

以下是计划验收场景，不代表已经通过的新测试。每项结果必须能够对应真实请求、数据状态或可观察页面行为。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 高一/高二公共内容纠错 | 复数对应字段同步，缺失的三角跳过，不插入章节 |
| 他人课程、无关同名课程 | 不出现在可修改目标内，不被同步修改 |
| 内容重排和重复引用 | 来源匹配不依赖下标；实例和学习结果互不串用 |
| 目标已有不同修改 | 预览出现冲突，未作明确处理时不覆盖 |
| 预览后发生编辑或归属变化 | 提交明确失败或要求刷新，旧工作内容保留 |
| 整批与逐项审核 | 支持两种操作，审核结论和意见按课程独立留档 |
| 部分通过、部分退回 | 只发布选中的已通过候选，其他课程继续旧版 |
| 通过后继续修改草稿 | 实际发布内容仍严格等于通过的候选快照 |
| 发布失败、重复请求和回滚 | 无半套结果或重复包；回滚追加修订并经过审核 |
| 学生未加入校本课程 | 正文、历史版本、启动入口和缓存均不能绕过准入 |
| 自主探索与教师预览 | 不污染正式课程名单、成绩或学生完成投影 |
| 沿用、补做与再次评分 | 历史保留，当前版结果有有效来源，不重复计分 |
| 运行中换版或撤权 | 在途尝试使用已绑定版本；撤权后停止写入 |
| 非法模板配置或缺失资源 | 明确阻止，不出现空白发布或假成功 |
| 后台任务重试与恢复 | 不重复通知、认定或记账，失败能定位与恢复 |
| 迁移与旧客户端 | 已有记录可对账，未知来源不猜测，不能通过旧入口绕审 |

### 5.1 工程与页面验收

验证迁移往返、权限正反向、并发编辑、真实 API、前端契约和三角色桌面/移动 Web 操作。主要操作覆盖正常、加载、空态、失败、冲突、重试及离页重入；验证键盘、触控、可读解释和数据一致性。

原有学习证据、幂等、事务、接口公开面与实验保护检查继续提供回归保障。对过时的源码形状或行数约束，应依据新架构修正其合同并保留真实行为断言，不能删掉能发现问题的测试。

### 5.2 性能与运行证据

沿用当前配置中的常规接口 500ms、管理聚合 1000ms、导出 5000ms 预算，在固定隔离数据集与明确硬件上记录耗时分布、请求次数和 SQL 数量。导出改为任务时，受理耗时与生成耗时分开报告，不混成一个通过值。

课程和发布列表有界分页，发布摘要不携带所有历史正文；列表与汇总的查询次数不得随返回课程数量线性增加。预览、审核及发布除耗时外还要验证事务和幂等正确性。

本地 SQLite 是本轮完整运行验收边界。保留 MySQL 迁移和查询兼容；真实 MySQL 并发、长期运行、公网部署与灾难恢复按准备部署的版本另作专项，不将兼容检查写成实机证明。
