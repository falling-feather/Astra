## 1. 最终完成定义

当前 V8.0 的“完成”指可在评审现场稳定讲解、操作和复验的本地展示版，不再等同于正式互联网产品上线。最终候选必须同时满足：

1. Windows 本机通过 `astra-local.ps1` 在 `127.0.0.1:9001` 一键启动，默认 SQLite 数据可重复初始化；不要求域名、公网 TLS、Windows 服务或正式 MySQL。
2. 登录发生在星序应用壳之前，学生、教师、管理员由服务端 Session 确定身份；越权页面与资源不能因前端隐藏失误而开放。
3. 学生从星序总览进入三个学习单元，至少能完整展示“目标 / 预测 / 操作 / 反馈 / 结果或解释”的代表课程路径，并留下可恢复的学习证据。
4. 教师能围绕现有课程完成班级选择、课程开放 / 锁定 / 隐藏、进度查看、作业或代码提交查看和反馈；不要求建设通用无代码内容平台。
5. 管理员能在星序统一后台查看并受约束地维护用户、教师、班级、组织、课程状态与审计信息；不开放原始表、任意 SQL 或无边界低代码写库。
6. 工科试验室、代码空间和未来星系在目录、课程页、反馈、移动端和页脚上具有一致的信息层级，同时保留各自的互动特征；Canvas、Three.js 只在确有教学价值的课程按需加载。
7. 代码空间继续提供浏览器学习运行、执行轨迹和正式提交留痕。未配置隔离判题器时必须如实显示 `runner_unavailable`，不把浏览器预检伪报为正式 accepted。
8. 关键演示路径通过自动化、桌面与 390×844 浏览器、角色权限、SQLite 账本和一键启动复验；无需用全站 88 个实验、学期级并发或压力测试证明展示版。
9. 项目结构、当前能力、演示账号 / 数据、启动方法、已知边界和后续工程在文档中能被非开发者理解，仓库不携带无调用旧页面、临时模板、构建缓存或测试证据。
10. 生产化能力保留已有设计和工具，但不再阻塞展示版完成，也不得被产品文案提前宣称为已上线能力。

展示版的价值判断顺序固定为：**能讲清楚 → 能完整操作 → 三角色数据能对上 → 关键错误能诚实降级 → 再考虑生产化增强**。这不授权绕过认证、权限、数据完整性、源码隔离等基础安全边界。

产品叙事固定为“可扩展多星系互动教学平台”：借鉴综合教学平台的课程、班级和教学协作结构，以可视化实验、代码执行追踪、跨学科互动和三角色数据闭环形成差异。现场材料不得用“全面替代”或“全面优于”某一成熟平台的泛化比较掩盖尚未完成的能力。

## 2. 十项问题与展示版处理

| 外部评审问题 | 当前展示版必须关闭 | 展示后再做 |
| --- | --- | --- |
| 1. 学习闭环未真正接通 | 三个学习单元的代表课程统一写入权威学习证据，刷新 / 离线恢复可解释，教师能看到同一事实 | 大规模事件配额、长期归档和学期级分析 |
| 2. 产品定位过于贪心 | 星序只呈现真实可用的三角色任务与三星系入口；删除伪入口、营销占位和重复后台 | 家长端、内容市场、社会化学习等新角色 |
| 3. 内容数量超过深度 | 优先精修每个星系的代表学习路径，保留目录但不宣称所有活动都已完成教学验证 | 全目录逐课学科专家审查和正式课程认证 |
| 4. OJ 只有契约没有产品 | 浏览器运行 / 追踪、正式提交、教师源码查看和诚实判题状态可演示 | 隔离 runner、隐藏测试、资源计量、部分得分和重判集群 |
| 5. 教师工作台像控制面 | 用教学语言完成发布节奏、进度、提交和反馈主路径，减少底层术语与诊断噪声 | 真实学校排课、外部通知和复杂逾期政策 |
| 6. 管理台形成可观测性幻觉 | 组织、人员、班级、课程和审计成为主视图，操作有影响确认与权威回读 | 运营指标体系、复杂数据质量规则和跨校治理 |
| 7. 教师可配置课程只有半真 | 教师可控制既有课程分块和可见性，学生视角与发布结果一致 | 通用互动课程工作室、任意新题型和送审市场 |
| 8. 技术债务过重 | 删除可证明无调用的旧文件，保持稳定模块边界，优先拆解影响展示和维护的热点 | 全量巨型文件重构、全部 legacy 生命周期清零 |
| 9. 测试证明被高估 | 用真实浏览器、三角色脚本、代表课程交互和 SQLite 账本证明现场主路径 | 真实课堂试点、低配设备实验、全站读屏和压力 / 容量测试 |
| 10. 正式发布条件不成立 | 明确标注本地展示版，不把 9001、SQLite 或 CI 外推为上线 | MySQL、域名、TLS、secret store、监控、备份恢复、生产回滚与专业合规复核 |

十项问题没有被删除，而是按当前作品性质分成“展示版必须关闭”和“展示后再做”。后置项恢复时必须在父文档建立新任务、目标环境和验收口径，不能悄悄重新成为当前阻塞项。

## 3. V7.6—V8.0 版本路线

| 版本周期 | 当前交付重点 | 退出门禁 |

| V7.7 代表课程体验 | 精修三个星系的代表课程和统一课程语言 | 每个星系至少两条可讲解代表路径；互动不只是知识文本，目标、预测、操作、反馈和解释结构完整 |
| V7.8 教师协同 | 发布节奏、学生进度、作业 / 代码提交与反馈 | 教师从星序完成一套“安排 → 学生学习 → 查看证据 → 反馈”的本地演示脚本 |
| V7.9 管理与整体打磨 | 管理治理、演示数据、移动端、视觉一致性和错误降级 | 管理员完成组织 / 人员 / 班级 / 课程调整并回读审计；关键路由桌面与 390×844 可用 |
| V8.0 展示版收口 | 一键启动、三角色串联、说明材料、全局回归与候选封装 | 全新本地数据目录可复现完整讲解；自动化、真实浏览器、SQLite 账本、文档和 Git 指向同一候选 |

版本推进只认对应退出门禁，不因日期、代码量、页面数量或测试数量自动升级。对当前展示没有帮助的基础设施不得抢占代表课程与三角色协同的开发时间。

## 4. 代表课程质量契约

代表课程不是“所有课程都重写”，而是从每个星系选择至少两条最能说明设计能力的学习路径，满足：

1. 页面首先说明学生要观察或解决什么，而不是解释用了什么框架。
2. 学生操作前必须做预测、选择或提出假设。
3. 互动至少包含一种有教学意义的状态变化：变量控制、Canvas 观察、执行轨迹、拖放 / 排序、判断反馈或按需 3D 场景。
4. 操作结果要回到知识因果或错误模型，不能只显示“正确 / 错误”。
5. 至少保留一处修正或再次尝试，让“玩中学”产生可见前后差异。
6. 课程具备稳定活动键、发布状态和权威证据映射；访问页面本身不计完成。
7. 教师能在工作台找到该课程、控制可见性并看到学生证据或提交。
8. 390×844 核心控件有可操作触达区，无根级横向溢出；键盘主路径与减少动效边界保持可用。

三星系六门代表课程的具体选择、主变量、常量、错误模型、证据事件、教师回读、事实来源与八分钟演示顺序，以 [`27-V7.7三星系六门代表课程教学与证据冻结契约.md`](27-V7.7三星系六门代表课程教学与证据冻结契约.md) 为实施基线。

其余已有课程可以保留为可浏览或 `demonstration-only`，但目录和文案必须诚实，不用“全部验证”“完整掌握”等表达扩大实际能力。

## 5. 跨模块依赖

```text
已完成：ARCH-001 模块边界 + BE-006 权威学习证据
                    │
                    ├──> PM-009 星序主路径 ──> FE-012 三单元接入 ──> QA-014
                    │
                    └──> CONTENT-001 代表课程
                                      │
                                      └──> UX-003 ──> BE-007 ──> FE-013 教师协同

FE-012 + BE-007 ──> DATA-001 ──> UI-003 管理治理
代表课程 + 教师协同 + 管理治理 ──> QA-013 展示脚本 ──> REL-008 / V8.0

ARCH-002 仓库瘦身可独立进行，但不得改写 FE-012 未提交候选。
```

一个任务只设一个实现主责组。前端、后端、内容与 QA 可以在不重叠文件和冻结接口上并行；QA 失败返回原主责组，不另开第二个实现组竞争同一缺陷。

展示版验收不要求四周真实课堂、30—60 名学生、真实 MySQL、生产域名或压力报告；也不能因此省略真实浏览器、角色权限、数据对账和错误降级。

## 7. 后置工程与停止规则

以下内容保留设计和已有工具，但在用户明确恢复生产化目标前一律不阻塞 V8.0 展示版：

- 真实 MySQL 适配实证、学期级数据、并发课堂和 p95 / p99 容量；
- 域名、TLS、Caddy / WinSW 四服务、secret store、日志监控、备份恢复和生产回滚；
- 隔离 OJ runner、隐藏测试、资源计量、重判和多租户容量；
- 通用教师内容工作室、外部 Webhook / GitHub / audit provider，以及学生 AI 助教、教师 AI 教学助手、AI 维护 / 管理助手；
- 四周真实课堂试点、全目录学科专家审查、目标司法辖区的专业合规复核；
- 全部 88 个实验的 legacy 生命周期清零和全站逐路由读屏认证。

AI 路线在父文档拆为三个互不冒充的条件任务：

1. `AI-001` 只面向学生当前课程提供有来源的提示、追问与解释，不能代答或直接写入完成 / 掌握。
2. `AI-002` 只为教师生成课程节奏、反馈或题目草案，发布、评分和反馈必须由教师确认。
3. `AI-003` 从只读诊断和治理建议开始，任何维护 / 管理变更都必须显示影响、由管理员确认、调用既有领域 API 并留下审计。

三项 AI 能力都不属于 V8.0 展示版退出门禁。当前没有 provider、对话入口或 AI 写入链；未来星系“数据科学与 AI”课程名、确定性规则推荐和统计摘要不能作为 AI 已实现的证据。

当前停止规则：

- 不继续增加课程数量；优先精修代表课程和串通三角色数据。
- 不新增仅装饰性的 Three.js、概念卡、统计卡或底层实现说明。
- 不开放任意 SQL、数据库表、原始 JSON、任意 DOM 或宿主脚本编辑。
- 不在 API 进程或宿主环境直接执行学生源码。
- 不为追求“全绿”伪造判题、学习完成、外部投递或生产环境证据。
- 发现权限绕过、敏感数据泄露、不可恢复迁移或写入无法对账时，仍必须先修复；“展示优先”不等于放弃基础正确性。
