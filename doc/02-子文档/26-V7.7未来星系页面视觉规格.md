## 1. 设计结论

1. 视觉概念定为“**证据观测台 / 六条研究航线**”：未来星系是学生进入六个跨学科方向、形成预测、操纵变量、读取证据并修正解释的深空研究台，不是卡片商城、素材陈列馆或持续播放的太空动画。
2. 页面统一工科试验室已经形成的模块顺序、进入节奏、导航逻辑和页脚逻辑；未来星系保留深空色彩、细线框、方向色和观测素材，不复制工科试验室的皮肤。
3. 信息架构严格分成未来星系主页、方向目录和具体课程页。方向目录只负责发现、状态和进入；三门课程必须是三个独立条目，其中 `open` 是普通链接，`locked` 是不可进入的状态行，`hidden` 不进入学生 DOM，不再用页内标签、轮播或视角切换冒充课程目录。
4. 课程页把教学任务置于视觉效果之前。每个可视化都必须帮助学生预测、比较、观察或解释；静态文字、访问、动画播放和随意点击不能冒充教学证据或完成。
5. 视觉层次优先通过空间、字号、边线和少量方向色建立，不使用密集玻璃卡片、发光边框墙、大面积渐变字、装饰性 3D 行星或持续旋转几何体。
6. 设计基准同时覆盖约 `1015×898` 桌面视口和精确 `390×844` 移动视口；两个视口不是事后缩放，而是同一阅读顺序下的双布局。

## 2. 视觉语言

### 2.1 色彩令牌

| 用途 | 令牌建议 | 使用边界 |
| --- | --- | --- |
| 页面底色 | `#030814` | 根背景；保持稳定，不使用高频星点动画 |
| 主内容底色 | `#050B19` | 课程与目录主体 |
| 抬升表面 | `#071225` | 观察台、证据区和状态区；同页不叠超过两层 |
| 主文字 | `#F5F8FF` | 标题、关键结论和输入值 |
| 次文字 | `#B5C4DA` | 正文和帮助文案；不得沿用对比不足的灰蓝 |
| 细边线 | `rgba(156, 190, 255, 0.28)` | 分区、路线和表格，不作为唯一状态表达 |
| 主动作 | `#8CE7FF` | 唯一主动作、当前焦点和关键证据 |
| 当前步骤 | `#FFB86B` | 当前教学步骤、需要修正的证据；不与错误态混用 |
| 成功 / 已完成 | `#83E0B5` | 必须同时有图标和文字 |
| 错误 / 冲突 | `#FF8F9D` | 必须附原因和修正入口 |
| 中性不可用 | `#8391A8` | 锁定状态；隐藏状态不向学生渲染 |

六方向色只用于左侧窄轨、编号、微型标识和观察图中的辅助系列，不接管全局主动作：

| 方向 | 色值 |
| --- | --- |
| 地球与宇宙 | `#86E7FF` |
| 工程系统 | `#FFC36A` |
| 数据科学 | `#BCA7FF` |
| 信息技术 | `#79B8FF` |
| 材料微观 | `#8FE0C0` |
| 人文可视化 | `#FF9FCB` |

所有状态同时使用图标、短标签和必要说明，禁止只靠颜色表达 `open / locked / completed / needs-retry`。

### 2.2 字体与文字层级

1. 继续使用项目现有无衬线字体栈与等宽数字字体，不增加网络字体或首屏字体请求。
2. 未来星系主页一级标题桌面使用 `clamp(3.5rem, 7vw, 4.75rem)`，移动使用 `clamp(2.625rem, 12vw, 3.25rem)`；不得恢复接近 `5.75rem` 且挤压正文的标题。
3. 方向页一级标题桌面 `3rem—4.25rem`，课程页一级标题 `2.5rem—4rem`；正文基准 `1rem / 1.75`，连续阅读宽度不超过 `68ch`。
4. 标签、状态和图例不低于 `0.75rem`；等宽字段只用于序号、单位、步骤和证据值，不用于长段正文。
5. 标题使用清楚的陈述句，避免只有氛围感的口号；课程首屏必须直接显示学习目标和模型边界。

### 2.3 空间与表面

1. 主容器最大宽度 `1200—1240px`；宽屏左右内边距 `32—34px`，移动左右内边距 `18px`。
2. 页面模块使用 `24 / 32 / 48 / 72px` 的纵向节奏；同一模块内部优先 `12 / 16 / 24px`。
3. 圆角只用于可操作的输入、状态组与观察台，建议 `12—18px`；普通文档区、路线行和页脚用直线分隔，不把全部信息装进卡片。
4. 阴影保持极弱，主要深度来自底色差和边线；文字、边框和交互状态必须在暗色背景上满足可读性。

### 2.4 图像与品牌素材

1. 未来星系主页首屏复用现有 `UI/future-galaxy/orbit-observatory.webp` 作为观测语义主视觉，必要时以 `future-galaxy-hero-sky.webp` 作轻量背景；概念与实现不得把两张大背景同时作为无意义叠层。
2. `future-galaxy-hero-nebula.webp` 只在概念对比证明其承担明确方向定位时使用；默认不与观测台素材同时加载。
3. 方向目录不使用占据首屏的大图；方向身份由窄轨色、核心问题、课程状态和编号建立。
4. 课程运行时中的图像、Canvas 或 Three 只承载观察证据；UI 文本、按钮、状态、图例和替代说明必须是 DOM。
5. ImageGen 只生成完整页面构图参考，不生成含真实可点击按钮、可读课程正文、伪造品牌标志或替代可访问文本的图片资产。

## 3. 共享页面骨架

### 3.1 全局导航

1. 导航逻辑与工科试验室一致：品牌 / 当前学习单元、回到星序、角色工作区和会话入口保持固定语义与位置，不另造一套未来星系身份系统。
2. 桌面导航保持单行；当前学习单元有文字和底线 / 窄轨双重指示。移动端收束为品牌、当前页面和单一菜单触发器，触发目标至少 `44×44px`。
3. 导航使用正常文档流或仅在不会遮挡课程标题时采用现有壳层行为；不得用高层级粘性玻璃条覆盖观察内容。
4. 页面必须具有跳至主内容链接、唯一 `main`、可辨认的 `nav` 和标题层级。

### 3.2 面包屑与状态

1. 方向页：`星序 / 未来星系 / 当前方向`。
2. 课程页：`星序 / 未来星系 / 当前方向 / 当前课程`。
3. 面包屑中的方向与课程目录是普通链接，可通过刷新、前进和后退恢复；当前项用文本而不是禁用按钮。
4. `open` 显示“可进入”；`locked` 显示锁图标、原因和返回目录动作；`hidden` 对学生完全不渲染；未知或错配路由显示明确错误与返回目录动作，不能落到第一课。
5. 共享 Router 是唯一 hash owner，只注册一个 `page-frontier`。canonical 路由为 `#frontier/<direction>/<course>`；旧方向 / 课程 hash 只执行一次 `history.replaceState`，不新增历史项。未知、错配、非法或多余路径使用固定诊断，不回显原始未知 slug。

### 3.3 页脚

1. 页脚复用工科试验室的三列逻辑：星序品牌 / 当前课程与学习单元 / 关于与边界；最下方单独显示版权或版本说明。
2. 页脚在正常文档流中，不固定、不悬浮、不遮挡完成动作。桌面三列，移动按品牌、课程、关于顺序堆叠。
3. 课程列在具体课程页显示返回方向目录、上一课、下一课；主页只显示未来星系与星序入口，不伪造课程上下文。
4. 页脚链接命中区不低于 `44px`，焦点样式与正文链接清楚区分。

## 4. 未来星系主页

### 4.1 首屏构图

1. 桌面首屏为左右两栏：左侧依次放置眉题、一级标题、平台主张、两句使用说明和“浏览六个方向”锚点；右侧是观测台素材和一条简短的“从预测到证据”说明。
2. 首屏不显示 18 门课程卡，不放大数字看板，不把“18 门课”作为完成率或质量证明。
3. 约 `1015×898` 时，首屏文字列最小 `420px`，图像列最小 `360px`，间距 `40px`；若不足则在 `900px` 左右切换为单列，避免标题与观测台互相挤压。
4. 移动首屏顺序为标题、主张、入口、裁切后的观测素材；主视觉高度约 `220—260px`，不得迫使方向入口落到多个屏幕后。

### 4.2 六条研究航线

1. 六个方向采用开放式路线行而不是六张等高玻璃卡：方向序号、名称、核心问题、三课状态摘要和进入箭头从左到右构成一行。
2. 每行只整行链接到方向目录，不直接跳第一门课；三课摘要只提供数量与状态，不在主页展开全部课程标题。
3. 鼠标悬停、键盘焦点和当前访问记录只改变窄轨、边线和箭头位移，位移不超过 `8px`，不能让整页持续漂浮。
4. 移动端每个方向为一条可进入的摘要行；如需展示三课摘要，只允许一次展开一个方向且其中课程仍是独立链接，不使用横向滑动卡带。

## 5. 方向目录页

### 5.1 方向识别区

1. 首屏依次为面包屑、方向编号 / 状态、方向名、一个核心问题和一段不超过 `68ch` 的说明。
2. 方向色只占左侧窄轨、编号和少量图例；页面主动作仍使用全局青色，保证六个方向的操作语义一致。
3. 方向页不得初始化课程 owner、Canvas、Three、学习计时器或证据客户端；发布状态只通过已登记的数据层读取。

### 5.2 三门独立课程

1. 每个方向只显示对应的三门独立课程，顺序与 25 号矩阵一致。
2. 每门课程行依次包含序号、课程名、可观察目标、模型 / 史料边界、状态标签和明确进入动作；只有 `open` 行可整行作为普通链接，状态与辅助说明必须能被读屏读取。
3. `locked` 行保留课程名、目标和原因，是不带链接语义的状态行；学生看不到 `hidden` 行，教师 / 管理员视图按既有权限显示状态。
4. 三门课程不是 Tab、segmented control、carousel 或同页视角；浏览器地址必须在进入课程时改变为该课 canonical hash。
5. 方向目录底部提供返回六方向和相邻方向入口，不加载该方向课程的运行脚本。

## 6. 具体课程页

### 6.1 固定模块顺序

课程页严格按以下阅读与键盘顺序渲染：

1. 全局星序导航。
2. 面包屑、课程发布状态和模型 / 史料边界。
3. 课程标题、学习目标、预计节奏和完成产物。
4. 非粘性的教学步骤轨：`目标 → 预测 → 操作 / 观察 → 反馈 → 修正 → 解释 / 完成`。
5. 预测区：选择或写下方向性预测及理由；没有预测不能把后续操作记为有效尝试。
6. 操作 / 观察区：一个主变量、明确基线、单位 / 模型标签、观察台和可读证据摘要。
7. 反馈区：指出证据支持或冲突的位置及原因，不只显示分数、红绿或“错误”。
8. 修正 / 重试区：保留第一次预测和证据，要求改变预测、变量选择或解释后再试。
9. CER 或领域等价解释区：主张、证据、推理 / 来源判断形成可提交产物。
10. 完成区：显示服务端派生状态、同步状态、返回方向目录、上一课和下一课。
11. 三列工程逻辑页脚。

步骤轨只用于位置与完成条件提示，不是课程切换导航；移动端为带文字的纵向进度，不使用只能左右滑动的横轨。

### 6.2 桌面观察构图

1. 在约 `1015×898` 下，操作 / 观察模块采用两栏：观察台最小宽度约 `560px`，证据 / 控制栏最小宽度约 `320px`，间距 `24px`。
2. 当可用宽度不足以同时满足两栏时，在约 `900px` 自动切换单列，顺序为任务提示、主变量、观察台、证据摘要、反馈与重试。
3. 观察台建议高度 `420—480px`；控制与证据区允许纵向滚动页面，不在模块内部制造难以发现的双重滚动。
4. 数值、单位、模型边界、图例与判读问题必须位于 Canvas 外的 DOM；Canvas 内只绘制确实需要空间关系的证据。
5. 课程页不使用固定底部动作栏；提交和完成动作位于对应教学模块中，避免与浏览器底部、移动键盘或页脚重叠。

### 6.3 移动观察构图

1. 精确 `390×844` 下，所有课程模块单列，根元素和模块不得出现横向滚动；表格使用语义化重排或局部明确滚动，不扩大根宽度。
2. 观察台高度约 `300—340px`，Canvas DPR 上限为 `2`；图例、刻度说明和证据值移到 Canvas 下方。
3. 输入、切换、重试和提交命中区至少 `44px`；相邻主动作之间至少 `8px`，不能把文本链接挤成难以点击的细行。
4. 数值控制优先使用带可见标签的原生输入、步进按钮或有限选项，不依赖精细拖拽；滑块必须提供键盘方向键和可读当前值。

## 7. 人文观察区重构

### 7.1 信息层级

1. 顶部先显示来源选择、出处、时间 / 角色语境和短摘录；来源必须来自 25 号矩阵登记的可追溯资料，不能把练习文写成史料。
2. 桌面观察主体为两栏：左侧来源摘录与标注最小 `300px`，右侧关系 / 证据图最小 `500px`；不足时直接单列，不压缩到重叠。
3. 柱形、关系节点和正文不再全部画进同一 Canvas。关系图只承担连接、距离或对比；图例、指标定义、证据表和主张文本位于图外 DOM。
4. 移动顺序固定为来源 → 图形 → 图例 → 证据表 → 主张 / 修正；不在 390px 宽度中并排柱图和关系节点。
5. 节点标签如无法在图中保持可读，使用编号或短名并在图后提供完整列表；不得用隐藏溢出掩盖遮挡。

### 7.2 教学交互

1. 学生先预测哪种语境 / 角色会改变表述，再选择来源、观察差异并标注至少两条证据。
2. 反馈必须区分“出处不足”“证据与主张不匹配”“把事后解释当作当时记录”等具体错误。
3. 重试保留原主张，要求补出处、替换证据或收窄主张；最终产物为带来源的史料主张—证据—推理。
4. 关系节点或柱形图只在帮助比较来源、角色和主张时出现；不能用随机节点布局或动画位移制造“复杂度”。

## 8. 动效、可访问性与运行时

### 8.1 动效

1. 普通过渡时长 `120—200ms`；位移不超过 `8px`，不使用持续漂浮、呼吸发光、背景视差或装饰性旋转。
2. `prefers-reduced-motion: reduce` 下取消平滑滚动、位移与非必要过渡；课程必须提供等价静态或事件驱动观察。
3. Three 只允许用于 `cosmos.orbital-scale` 的尺度 / 视角观察；不因主页、方向目录或其他 17 门课程加载 Three。

### 8.2 键盘与读屏

1. 所有普通链接保持浏览器原生 Tab 行为；方向键只用于明确声明并正确实现的复合控件，不截获页面或链接列表的方向键。
2. `:focus-visible` 使用高对比青色外框与偏移，不能只改变背景；焦点顺序必须与视觉阅读顺序一致。
3. Canvas / Three 旁提供可聚焦控制、文本证据摘要、当前变量与 `aria-live` 结果；图像提供与教学用途相符的替代文本。
4. 错误、锁定、同步中和未同步均有可读文字；不能只使用颜色、图标、动画或 toast。

### 8.3 按需加载与释放

1. 未来星系主页、方向目录、锁定 / 隐藏 / 未知 / 错配 / 非法路由不得请求课程内容模块，也不得创建课程 owner、evidence controller、Canvas、Three、RAF、ResizeObserver 或学习证据计时器。
2. 18 门课程正文与教学记录按课程拆为独立模块；只有精确 `open` 且访问授权通过的课程加载自己的内容模块、唯一 owner 和 evidence。hidden 内容不得因统一静态 bundle、预加载或 DOM 模板而泄露。
3. 进入具体课程后只加载该课程需要的运行时；普通 DOM / Canvas 课程不请求 Three 模块，只有 `cosmos.orbital-scale` 可以请求 Three。
4. 离开课程、返回目录、切换角色、登出和前进 / 后退时必须释放 RAF、事件监听、Observer、Canvas context、Three renderer / geometry / material / texture 和 evidence controller。
5. 开发与 QA 暴露可检查的资源计数或等价诊断；页面离开后回到基线，重复进入不得线性增长。

## 9. ImageGen 概念与实现门禁

### 9.1 概念图交付

## 10. QA 忠实度账本

`QA-015` 除功能门禁外，至少逐项比较以下视觉契约：

1. 信息架构：主页、方向目录、课程页职责分离，三课不是标签。
2. 字体与密度：标题不挤压正文，正文宽度和 1015×898 双栏满足本规格。
3. 色彩与状态：深空底色、全局青色、克制方向色及图标 + 文字状态一致。
4. 观察构图：主变量、观察台、证据、反馈和重试顺序清楚；人文图形无文字 / 柱形 / 节点遮挡。
5. 导航与页脚：与工科试验室逻辑一致，正常文档流，无固定遮挡。

7. 运行时：非目标页不加载课程可视化；离开课程后资源计数回到基线。

QA 截图、DOM / console 证据、资源计数和概念对照必须指向同一精确提交；第三方扩展噪声单独登记，不得混入产品结论。
