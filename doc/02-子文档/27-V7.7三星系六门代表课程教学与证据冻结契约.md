六课共同遵守：

1. 页面顺序固定为“学习目标 → 预测 → 操作 / 观察 → 反馈 → 修正 → 解释 / 完成”；答案不得与预测同屏首显。

3. 访问、播放、点击、拖动、节点数量、公开样例通过和客户端自写 `completed` 均不构成完成。
4. 六课统一要求 `started / predicted / attempted / corrected / explained` 五类学习事实。第一次判断正确时，`corrected` 记录补充适用条件、模型限制或证据强度修订，不能用空事件凑数。

6. 教师视图只展示预测、尝试序列、修订、解释与必要参数摘要；不展示完整源码、长开放文本、敏感材料或底层事件实现术语。

## 2. 工科试验室代表课程

### 2.1 `physics.mechanics`：恢复系数与第一次反弹高度

- **稳定事实与缺口**：当前 owner 为 `pages/physics/physics.js`，已经具有固定落高、`e=0.40 / 0.80` 两次受控竖直落球、第一次峰值测量、课程专用修正与共享学习证据；自由探索不写领域事实。教师发现接口已按本课有限事实矩阵解释参数，FE-013 尚未把它渲染进教师工作台。
- **学习目标（3—4 分钟）**：在落高、重力、半径、初速度和阻尼相同条件下，比较 `e=0.4` 与 `e=0.8` 的第一次反弹高度，并用恢复系数与理想模型限制解释差异。
- **预测**：操作前选择哪次反弹更高，并判断 `e` 加倍后高度约为 2 倍、4 倍还是无法仅凭该表述判断；必须写出理由。
- **变量、常量与观察**：只操纵 `e`；固定竖直释放、初始高度、重力、半径、水平初速度为 0、阻尼为 0；记录 `H`、第一次峰值 `h`、`h/H` 和两条轨迹。
- **典型错误**：把 `e` 当重力或能量来源；认为高度与 `e` 线性变化；把半径当质量；把教学阻尼当真实接触摩擦系数。
- **分层反馈**：先提示“只比较第一次峰值，不看尾迹长度”；再说明恢复系数是碰撞法向相对速度之比，而由速度到高度还经过平方关系；修正仍由学生完成。
- **重试与完成**：恢复统一落球预设，只改 `e` 各运行一次，提交两行测量表，并以“观察—关系—理想条件”解释。只说“更高”、同时改变多个参数或只拖球不算完成。
- **证据与教师回读**：`minimum_attempts=2`；尝试记录 `e/H/h/预设`，教师只按第 8 节有限事实回读预测、两次受控参数与 `h/H`、修订和模型限制；预测理由正文不回显。
- **事实门禁**：风险 **P1/C**。把“牵引力”改为“初速度”，“摩擦 μ”改为“阻尼 / 教学耗散参数”，“能量”改为“能量代理”。依据：[OpenStax College Physics 2e §8.5](https://openstax.org/books/college-physics-2e/pages/8-5-inelastic-collisions-in-one-dimension)。
- **V7.9.76 首片消费入口**：`FE-025` 必须继续消费第 9.2 节的顺序门、观察快照、错误分支与解释量规；本节的 3—4 分钟仅是既有演示片段时长，不等于完整教学活动课时。

### 2.2 `mathematics.derivative-application`：由导数符号判断单调性与极值

- **稳定事实与缺口**：当前 owner 为 `pages/mathematics/derivative-application.js`，已有函数曲线、切线、导函数、单调区间与极值标注，未接共享学习证据。当前答案过早显露，且“`f′=0` 处即极值点”是错误的一般化。
- **学习目标（4—5 分钟）**：以 `f(x)=x³−3x` 为高中主线，由切线方向判断导数符号，再由临界点两侧符号变化判断单调性和局部极值。
- **预测**：隐藏答案图层后，预测 `x=0`、`x=2` 处切线方向，并判断 `x=-1`、`x=1` 的极值类型及所需证据。
- **变量、常量与观察**：只操纵切点 `x₀`；固定函数和坐标范围；分阶段观察切线方向、`f′(x₀)`、三个区间的导数符号和临界点两侧符号变化。
- **典型错误**：把函数值当导数，或把 `f′>0` 理解为图像位于 x 轴上方；把 `f′=0` 当极值充分条件；混淆局部极值和闭区间绝对最值。
- **分层反馈**：先要求描述切线从左到右上升还是下降；再说明导数符号描述局部增减，临界点仍须比较左右符号；学生补全符号表后再重判。
- **重试与完成**：隐藏导函数后重新选择两个切点，提交两处斜率符号、完整符号表，并解释为什么不能只凭 `f′=0` 判断极值。只拖滑块或打开答案不算完成。
- **证据与教师回读**：`minimum_attempts=2`；producer 落地后，教师只按第 8 节有限事实回读切点、初始判断、符号表、是否出现“驻点即极值”错误及结论 ID，不回显解释正文。
- **事实门禁**：风险 **P1/B**。删除“`f′=0` 即极值”，高中主线不压入泰勒展开。依据：[教育部课程标准说明](https://jsj.moe.gov.cn/n2/1/1/1507.shtml)、[OpenStax Calculus §3.1](https://openstax.org/books/calculus-volume-1/pages/3-1-defining-the-derivative)、[OpenStax Calculus §4.5](https://openstax.org/books/calculus-volume-1/pages/4-5-derivatives-and-the-shape-of-a-graph)。

## 3. 代码空间代表课程

### 3.1 `control-flow.loop-boundary`：`<` 与 `<=` 的循环边界

- **稳定事实与缺口**：现有 manifest、浏览器 JavaScript runner、执行轨迹、正式提交 adapter 和共享学习证据均已存在。当前本地运行错误可能与正式 `runner_unavailable` 混码，轨迹未突出第一次为假的最终条件检查。
- **学习目标（3—4 分钟）**：在初值、步长、边界和循环体不变时，解释 `<3` 与 `<=3` 的循环体执行次数、最终输出和第一次 false 时的状态。
- **预测**：`count=0`、每轮加 1、边界为 3 时，分别填写两种运算符的执行次数、输出和第一次 false 时的 `count`。
- **变量、常量与观察**：只改关系运算符；固定初值 0、步长 1、边界 3 和循环体；记录每次条件值、状态更新、循环体次数、最后 false、浏览器输出和正式 runner 精确状态。
- **典型错误**：认为 `<3` 最终停在 2；把条件检查次数当循环体次数；把浏览器通过当正式 accepted；把 `runner_unavailable` 当答案错误。
- **分层反馈**：先把条件检查和循环体执行分成两列；再说明 `while` 先检查再执行，第一次 false 仍是轨迹证据但不会进入循环体。
- **重试与完成**：恢复初始代码，重填两条轨迹，再做浏览器预检；runner 可用时才正式提交。解释两种运算符为何相差一轮。只看输出或浏览器 pass 不算完成。
- **证据与教师回读**：`minimum_attempts=2`；浏览器运行和正式提交动作分开记录，正式 accepted 不是课程完成硬条件。教师回读有限预测、浏览器预检和修订；正式 accepted / runner 状态只能从 code-submissions / attempt 回读，不能由学习证据中的 `cursor.judge` 推断。
- **事实门禁**：风险 **P1/B**。必须区分 `browser_runtime_error` 与 `runner_unavailable`，轨迹不承担正式判题。依据：[ECMAScript 2025 While Statement](https://tc39.es/ecma262/2025/multipage/ecmascript-language-statements-and-declarations.html#sec-while-statement)。

### 3.2 `debugging-testing.minimal-case`：缩减、复现、修复与回归

- **稳定事实与缺口**：现有 manifest 与共用 challenge / C Worker 外壳，未接共享学习证据。当前代码按“非零元素计数”实际正确，提示把 `!=0` 改成 `==0` 会改变需求；没有失败输入、缩减、复现和回归，不能作为最小反例课程。
- **学习目标（5—6 分钟）**：从四元素失败输入缩到仍保持同一失败的单元素输入，定位谓词错误，修正后同时重跑最小输入和原输入。
- **冻结场景与预测**：规格为“统计严格大于 0 的元素”；缺陷谓词为 `!=0`；输入 `[4,0,-2,7]` 期望 2、实际 3。学生先预测负数、零或正数哪类能单独保留失败。
- **变量、常量与观察**：先只缩输入，复现 `[-2]` 的期望 0 / 实际 1 后才解锁源码；固定规格、expected、runner 和失败签名；观察规模 `4→1`、逐步 `count`、修复后最小与原输入双通过。
- **典型错误**：未复现就改代码；修改 expected；把“最小”理解为数值最小；硬编码当前输入；只测最小输入而不回归原输入。
- **分层反馈**：先提示每次删除后确认仍是同一种 expected / actual 差异；再说明最小反例是继续删除就不再复现；学生填写负数、零、正数的谓词真假表。
- **重试与完成**：顺序固定为“原失败 → 缩减 → 最小失败 → 修源码 → 最小通过 → 原输入回归通过”；提交缩减链和一般性修复解释。跳步、改 expected 或只运行一次不算完成。
- **证据与教师回读**：`minimum_attempts=4`，至少覆盖原失败、最小失败、修后最小、原输入回归；不回显 revision hash 或完整源码。producer 落地后，教师按第 8 节四个离散阶段回读规模、失败签名、修复先后和两次回归。
- **事实门禁**：风险 **P0/C**。starter、规格、测试、提示和全过程必须整体重写。依据：Zeller & Hildebrandt, [“Simplifying and Isolating Failure-Inducing Input”](https://www.cs.purdue.edu/homes/xyzhang/spring07/Papers/delta-debugging.pdf), IEEE TSE 28(2), 2002, DOI `10.1109/32.988498`。

## 4. 未来星系代表课程

### 4.1 `engineering.load-path`：理想桁架的荷载重分配

- **稳定事实与缺口**：当前兼容 owner 为 `pages/engineering/bridge-truss.js`，有理想平面桁架求解、支反力和杆件轴力着色，未接 Future canonical 或共享学习证据。“哪几根杆先变红”与青色拉 / 橙色压图例冲突；固定容量没有材料、截面或屈曲依据。
- **学习目标（4—5 分钟）**：在理想桁架近似下，把同一 60 kN 载荷由 B 移到 C，用支反力、代表杆轴力和一个节点平衡解释重分配；D 工况用于修正后的镜像检查。
- **预测**：预测 B→C 后左右支反力会更接近还是更悬殊，GH / CD 轴力绝对值如何变化，并给出一个节点平衡理由。
- **变量、常量与观察**：只操纵载荷节点 B / C / D；固定 60 kN、15 杆、几何、支座和理想铰接，隐藏拆杆与安全系数；观察 `Ay/Ey`、GH / CD 拉压与大小、节点 `ΣFx/ΣFy` 残差。
- **典型错误**：把力当作沿唯一道路流动；把红色当压杆或危险；把近零杆理解为所有工况恒为零；把理想模型和合成容量当真实桥梁设计结论。
- **分层反馈**：先比较左右反力，再看杆件；随后说明理想桁架由每个节点二维平衡求轴力，移动载荷会同时改变多个节点方程。
- **重试与完成**：按 B→C→D 运行，其他量锁定；提交三工况表、一个节点平衡解释和模型未覆盖项。只点节点、只看颜色或宣称完成真实设计不算完成。
- **证据与教师回读**：`minimum_attempts=3`；producer 落地后，教师按第 8 节回读是否锁定工况、三组反力 / 杆力、节点残差、修订与模型限制。
- **事实门禁**：风险 **P0/B**。首屏和解释区常驻“理想二维桁架教学近似”；修正颜色问题，隐藏或标注“合成教学容量”。依据：[Engineering Statics: Trusses](https://engineeringstatics.org/Chapter_06-trusses.html)、[Method of Joints](https://engineeringstatics.org/method-of-joints.html)、[MIT truss experiment](https://ocw.mit.edu/courses/1-105-solid-mechanics-laboratory-fall-2003/resources/exp4_03/)。
- **V7.9.76 首片消费入口**：`FE-024` 必须继续消费第 9.3 节的“预测—改变工况—观察快照—判断—纠正—解释”Future 合同；该合同不是当前页面能力声明。

### 4.2 `humanities.claim-review`：双来源证据与主张修订

- **稳定事实与缺口**：当前兼容 owner 为 `pages/humanities/text-lab.js`；`pages/humanities-futures/text-lab.js` 并不存在。现状是自编文本的词频 / 共现观察，未接 Future canonical 或共享学习证据，也没有“材料—证据—主张—反例—修订”流程。
- **学习目标（5—6 分钟）**：使用两份带来源元数据的 Apollo 11 一手材料，判断“着陆阶段的计算机警报几乎导致任务失败”应被支持、限定还是暂不判断，并据支持与限制证据修订主张。
- **预测**：材料展示前选择初始分类，并说明什么证据会证伪或迫使自己缩小“几乎导致失败”的范围。
- **变量、常量与观察**：依次切换实时通信记录和事后技术复盘；初始主张在修订前锁定；记录来源 ID、时间、角色、实时 / 回顾语境，以及证据属于支持、挑战或不确定。词频阈值仅作副工具。
- **典型错误**：用词频证明主张；用单一一手材料证明宽泛因果；把未提及当反证；把不同视角判成一方虚假；把节点点击当完成。
- **分层反馈**：先核查谁、何时、在什么语境产生材料；再说明实时记录与事后复盘回答不同问题，交叉核查往往只支持更窄的陈述。
- **重试与完成**：加入第二来源、调整证据角色或缩小时间 / 因果范围；完成需要两来源、支持与限制证据各一、修订主张和待查问题。只看词频、点节点或贴真假标签不算完成。
- **证据与教师回读**：`minimum_attempts=2`；节点点击不计事件。producer 落地后，教师只回读初始分类、来源 / 证据角色、修订 ID 和下一问题 ID；原主张、修订主张与问题正文均不回显。
- **事实门禁**：风险 **P0/C**。保留页面壳和共现副工具，替换 corpus、通用答案和完成逻辑；冻结示例结论为“需限定”，不得截取材料预设真 / 假。依据：[NASA 实时通信记录](https://ntrs.nasa.gov/citations/20160014392)、[NASA Apollo 11 Technical Crew Debriefing](https://www.nasa.gov/wp-content/uploads/static/history/alsj/a11/a11tcdb.html)、[Library of Congress 一手资料分析指南](https://www.loc.gov/programs/teachers/getting-started-with-primary-sources/guides/?reload=no)。

## 8. 教师有限事实 v1 契约

### 8.1 全局投影门禁

教师课程事实只按四元组查表：

```text
(activity_key, event_schema_version, event_type, exact leaf path)
```

当前唯一支持的 `event_schema_version` 为整数 `1`。它由服务端事件行参与查表，不要求前端根据响应自行猜测版本。投影必须遵守：

1. 只有下列六个精确 `activity_key`、版本 `1`、已登记 `event_type` 和精确叶路径可以进入 `evidence_summary.facts`。未知 activity、schema、event、路径或多余嵌套叶一律省略，并令 `truncated=true`。
2. 字符串只允许矩阵中列出的协议枚举原值；枚举由批准控件产生并映射为固定中文标签，不是开放文本。未知枚举省略并令 `truncated=true`。
3. 数值必须是 JSON number、不得是布尔值、必须有限、位于登记范围内并满足最大小数位。精度按解析后的数值校验：`abs(value − round(value,N)) ≤ 1e-9`，不依赖 JSON 原文末尾零。`NaN`、无穷、越界、超精度或类型漂移一律省略并令 `truncated=true`。
4. 标为“组合”的叶必须整组出现并满足同行映射。缺叶、交叉不一致或只通过部分校验时，整组课程事实不显示，并令 `truncated=true`，不得拼出误导性半条观察。
5. 每个事件最多 12 个 facts；按本文表格自上而下稳定取值。即使未来 producer 新增字段，也不能挤掉既有字段；第 13 项及以后省略并令 `truncated=true`。
6. `started`、服务端派生 `completed / transferred` 和 administrative correction 只显示外层事件类型、发生时间与纠正链状态，不提供课程专属 facts。服务端完成表示规则满足，不等于教师判定“已掌握”。
7. 预测理由、解释、反馈、教师纠正原因、源码、revision / request hash、`source_ref`、原主张、修订主张、下一问题正文、token / Cookie / 密钥、任意 `artifact.ref` 及未知 nested raw 均不在课程矩阵中；活动级投影必须省略并 `truncated=true`。BE-013 的教师课程摘要已丢弃旧通用 `value_type / value_size` 元数据，正文及可辨识片段始终不得进入 facts 或中文标签。
8. facts 是“学生记录 / 页面观测”的有限转述，不是服务端重新判科目正确性。中文标签不得把 `reported_correct` 写成“答案正确”，不得把结构化解释写成“解释合格”。

外层事件类型的固定教师标签为：`started` → `开始学习`、`predicted` → `提交预测`、`attempted` → `完成一次尝试`、`corrected` → `学生修订`、`explained` → `提交解释`、`completed` → `系统确认完成`、`transferred` → `历史规则迁移`。teacher correction 只显示为 `教师纠正记录`，不得与 learner `corrected` 混写。

以下表格中的“整数”要求无小数部分；“≤N 位”指十进制小数位上限。所有中文标签均为教师端固定文案。

#### 9.3.2 预测题、观察题与答案释放

#### 9.3.4 观察快照、最小变化与冻结基准

每次有效工况由第 8.6 节 11 叶原子组成：`operation`、`load_node_id`、`load_kn`、`Ay`、`Ey`、`GH` 数值 / 类型、`CD` 数值 / 类型、`residual_fx`、`residual_fy`。必须以结构化 DOM 表显示同一内容；Canvas 颜色、节点点击或“求解成功”字符串均不能补造缺叶。

| 阶段 | 节点 / 变化 | Ay / Ey (kN) | GH (kN) | CD (kN) | 学生必须判断 |
| --- | --- | --- | --- | --- | --- |
| 基线 | `B` | `45.0 / 15.0` | `-30.0`，受压 | `22.5`，受拉 | 左右反力不均；记录符号与类型 |
| 最小有效变化 | `B→C` | `30.0 / 30.0` | `-60.0`，受压 | `45.0`，受拉 | 反力更接近，`|GH| / |CD|` 均增大 |
| 纠正 / 镜像 | `C→D` | `15.0 / 45.0` | `-30.0`，受压 | `37.5`，受拉 | B / D 支反力镜像，但 CD 不被宣称完全镜像 |

三行都固定 `60 kN`；`Ay+Ey=60±0.1 kN`，残差各在 `[-0.05,0.05] kN`。这些数值只冻结当前 15 杆 solver 的验收基准，不是课标事实、真实桥梁测试值或通用桁架定律。

#### 9.3.5 误区、错误分支与纠正动作

| --- | --- | --- | --- |
| `EN-M01-no-change` | 重复运行 B，或 `no-redistribution` | 标出 B / C 自变量列，要求先确认唯一变化是否发生 | 恢复 60 kN / full，完成 B→C 两份快照后再判断 |
| `EN-M02-single-path` | `single-load-path`，只沿一条杆画“力流” | 提示每个节点同时满足二维平衡，要求比较 Ay / Ey 与两根杆 | 运行 D，提交 `load-redistributes-by-equilibrium` 并引用 B / C 数值 |

#### 9.3.6 解释量规、教师有限事实与完成规则

| 维度 | `0` | `1` | `2` |
| --- | --- | --- | --- |
| 主张 | 无结论或仍坚持唯一道路 / 颜色结论 | 只说“荷载会变化” | 明确荷载节点改变会按节点平衡重分配支反力与杆力 |
| 证据 | 无数值快照 | 只引一工况或一类量 | 引用 B / C 的 Ay / Ey 及 GH / CD 至少各一组比较 |

#### 9.3.7 模型、安全与可访问性

- **模型限制**：理想二维、铰接节点、杆件只承受轴力、线性静力、小变形、集中节点荷载；不含自重、材料与截面、连接刚度、屈曲、疲劳、动力 / 冲击、侧向稳定、制造偏差、地基与规范荷载组合。当前合成 `130 kN / safetyFactor` 不是工程容量或安全系数依据，受控课必须隐藏。
- **安全**：本课不提供现实桥梁选型、承载评估或施工建议；“平衡残差小”只说明当前数值求解内部一致，不表示结构安全。若扩展到实体桁架试验，加载装置、构件破坏、飞散与人员隔离必须另按学校实验规范评估。
- **可访问性**：所有阶段与节点选择键盘可达；载荷移动必须可用按钮 / 单选完成，不依赖拖拽；拉 / 压同时用正负号和中文文本表达，颜色不得独立传义；三工况有结构化表格、表头与单位；求解、错误和保存状态使用可感知状态消息；焦点随预测→B→C→判断→D→解释移动；支持减少动效；核心控件按项目 `≥44 px` 门槛验收。
