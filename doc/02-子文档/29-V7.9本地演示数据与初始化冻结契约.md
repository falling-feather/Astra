## 1. 当前稳定事实

1. `astra-local.ps1` 已提供 Python 3.12+、锁定依赖、Alembic 升级、显式 SQLite `DataDirectory`、`127.0.0.1:9001`、目录互斥、外部 provider / worker 关闭和可选 `-InitializeDemoData`。
2. 启动脚本可选执行安全的交互式管理员 bootstrap；密码从 UTF-8 stdin 输入，不经命令行参数或文件。
3. 用户表只保存 PBKDF2-SHA256 哈希、随机盐和 210,000 次迭代，不存在明文密码列。
4. 默认启动仍只迁移数据库并初始化静态内容；显式 `-InitializeDemoData` 才会在 Uvicorn 启动前经现有 HTTP API 创建或核对学校、班级、14 门课程、42 个单元、发布计划、学习证据、作业、反馈、代码降级与三角色演示链。没有 reset 或直接表写入开关。
5. `sqlite-qa-ledger.py` 是只读数量与迁移账本，不能证明非空演示数据的语义正确；迁移检查后续必须读取动态 Alembic head，不继续写死 0051。
6. `role-workflows-proof.cjs` 可参考三角色操作顺序，但它随机、非幂等、依赖浏览器且只覆盖一门泛化课程，不能直接作为运行时初始化器。
7. pytest fixture 主要使用内存库或直接 ORM 设值，只适合测试，不得复制为产品 seed。

## 2. 本地账号与组织合同

固定、无真实个人信息的身份：

| 用户名 | 角色 | 显示名 | 权限范围 |
| --- | --- | --- | --- |
| `astra_demo_admin` | admin | 演示管理员 | 全局治理与审计 |
| `astra_demo_teacher` | teacher | 演示教师 | 演示学校、班级和挂接课程 |
| `astra_demo_student` | student | 演示学生 | 演示班级学习、提交和反馈回读 |

固定领域对象：

- 学校：`星序本地演示学校`，区域 `本地演示`。
- 班级：`星序 V8 综合演示班`，年级 `10`，学期 `V8-local`。
- 教师通过领域 API 创建学校、班级和课程；学生通过现有 join / membership 领域 API 进入班级。

凭据固定为“稳定用户名和数据图 + 每个全新目录独立生成的一次性强密码”：

1. 三个密码分别随机生成，只在首次初始化终端显示一次。
2. 密码不写入仓库、配置、环境变量、审计记录、manifest 或数据文件；SQLite 只保留哈希。
3. 同一目录重跑且账号已存在时，通过交互式 `getpass` 读取操作者输入的既有密码；不得回显、保存、静默重置或重新打印密码。
4. 凭据遗失时使用新的显式 `DataDirectory` 重建，不提供公开默认密码，不覆盖旧库。

## 3. 最小课程目录：14 Course / 42 Unit

六门代表课程在产品中是 `activity_key`，后端 Course 是更上层目录。代码空间和未来星系 manifest 都要求完整的六方向 / 六组父课程存在；只创建六条代表 activity 可能使整个星系适配失败。

最小父课程：

- 工科：`physics`、`mathematics`。
- 代码：`program-start`、`control-flow`、`data-functions`、`algorithm-thinking`、`debugging-testing`、`challenge-submission`。
- 未来：`earth-space`、`engineering-systems`、`data-ai`、`information-technology`、`materials-science`、`humanities-futures`。

共 14 个 Course、42 个 Unit：

- 工科两个 Course 各 3 个代表 / 兼容 Unit。
- 代码六个 Course 各 3 个 Unit。
- 未来六个 Course 各 3 个 Unit，与 25 号六方向 / 18 课程矩阵一致。

其余目录 activity 保持存在并使用诚实发布态，防止完整 manifest 因缺项失效。所有已发布代表 Unit 都要绑定完成规则，不能只给一个 activity 建规则。

DATA-003 的课程级 profile：

| 代表活动 | `producer_mode` | `course_fact_status` | 当前演示 payload 边界 |
| --- | --- | --- | --- |
| `physics.mechanics` | `frontend_precise` | `precise` | 固定 preset、`e=.40/.80`、两档观测与 learner correction 的当前结构化形状 |

## 5. 额外演示事实

1. **力学教师锚点**：3 次 attempted；教师通过追加式 correction 纠正其中 1 条，仍保留 2 条有效尝试并维持服务端完成。原事实和纠正关联均可回读。
2. **控制流单课程教师样例**：`control-flow.loop-boundary` 除完整五类事实、可纠正 attempt 与真实 `runner_unavailable` 代码提交外，再提供一份 submitted、尚待教师处理的短合成作业，使 28 号七分三十秒脚本可在同一班级、同一课程内连续演示安排—进度—证据—纠正—反馈—代码—学生预览。
3. **人文待处理作业**：保留一份 submitted、尚待教师处理的短合成作业，继续支持 Future 课程独立验收，不因控制流补样被移除。
4. **力学已反馈作业**：一份已评分并带短教学反馈的作业，学生 review API 可读取同一结果。
5. **控制流 runner 降级**：创建代码题并在 disabled runner 下得到真实 `runner_unavailable`；不得预写或伪装 accepted。
6. **管理员课程状态冲突**：`engineering-systems` 初始为 draft。先完成课程、Unit、挂班、release plan 与规则定义，再以 `expected_status=draft` 发布并回读 published；只有发布完成后才写入 `engineering.load-path` 学习证据。随后用过期 expected status 请求其他状态，必须返回 409、不自动重试，并回读 published、影响计数和审计。
7. 所有证据、作业、源码和反馈使用短小合成内容，不包含真实姓名、邮箱、代码、长文本或第三方秘密。

## 6. 目标启动命令与初始化流程

目标命令：

```powershell
powershell -ExecutionPolicy Bypass -File .\astra-local.ps1 `
  -DataDirectory <全新目录> `
  -InitializeDemoData
```

`-InitializeDemoData` 只允许在 development + SQLite + 本机地址下运行；遇到 MySQL、远程绑定或非本地环境必须拒绝。

初始化顺序：

1. 建立 / 复用 `.venv` 并校验锁定依赖。
2. Alembic 升级到动态 head。
3. 首次初始化为缺失账号生成并仅显示一次三角色凭据；账号已存在时以 `getpass` 读取既有密码。
4. 通过 bootstrap / register / login 创建或核对账户，认证凭据只驻留于当前进程内存。
5. 全部通过领域 API 创建或核对学校、班级、14 Course、42 Unit、挂班与 release plan。
6. 创建或核对覆盖全部已发布 Unit 的完成规则；对 `engineering-systems` 执行管理员课程状态 CAS，确认 published 后再写六门课的真实五类证据、作业、反馈与代码降级。
7. 执行教师事件发现 / 纠正，再制造一次过期 `expected_status` 的管理员课程状态冲突并权威回读。
8. 执行语义回读验证，生成结构化报告，再启动 `127.0.0.1:9001`。

初始化器不得直接写 ORM、SQL、原始表或迁移内部状态。

## 7. 同目录幂等合同

1. 对象存在时先 GET 并比较稳定字段，不能笼统吞掉 409。
2. release plan 先 GET 当前版本，仅在差异存在时执行 CAS。
3. 完成规则通过定义哈希核对，避免每次生成新版本。
4. 学习证据使用稳定 `client_event_id`、固定载荷和固定逻辑时间做精确 replay。
5. 作业按 unit + title 查找；提交、评分、代码题、代码提交和纠正均先权威回读。
6. 课程已经处于 published 时不重复切换状态，也不制造额外审计。
7. 同一目录连续运行两次后，账户、领域对象、事件、提交和纠正不得增殖；初始化器拥有的领域审计不得重复。每次正式登录必然产生的 `auth.login.success` 等认证审计须单独计数和说明，不得被误判为 DATA 幂等失败，也不得借此放宽课程、发布、证据或治理审计的精确幂等。
8. fresh 初始化与后续重跑必须复用同一 profile 声明；不得因重跑把 generic fallback 升格为专属 producer，或让 `producer_mode / course_fact_status / fixture_provenance` 漂移。

## 8. 语义回读报告

报告至少验证：

- 三个 `/api/users/me` 的角色与身份。
- 学校、班级、14 Course、42 Unit、挂班和 release plan。
- 六门代表课程的恢复状态、完成规则和服务端 completed。
- 六门课程各自的 `producer_mode / course_fact_status / fixture_provenance`；不得再要求六课 `summary_facts` 统一非空。
- BE-007 教师事件发现得到的事件 ID、安全摘要和纠正关联。
- 教师 aggregate / progress 分页。
- pending / graded 作业和学生反馈。
- `runner_unavailable` 提交、attempt 与授权源码回读。
- 管理课程状态、预期 409、影响计数和审计 before / after / reason。

初始化报告明确标记：

> 本数据为合成演示证据，用于复验产品闭环，不代表真实学生学习时长、掌握程度或课堂试点。

报告中的 `summary_facts` 只汇总教师安全投影返回的 fact key，不能恢复被省略的学生正文，也不能作为 producer 能力判定来源；课程能力只读上述显式 profile 字段。

## 9. 安全重置

1. `Ctrl+C` 停止当前本地实例。
2. 指向另一个全新的、显式 `DataDirectory`。
3. 重新执行初始化。

不得自动删除或覆盖默认 / 当前数据目录；旧目录保持可恢复。若未来提供清理命令，必须另建任务、解析并验证绝对路径，且要求显式确认。
