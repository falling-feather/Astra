## 1. 项目定位

星序 Astra 是面向高中与大学初阶学习者、教师和平台管理员的可扩展多星系互动教学平台。产品以交互实验和知识探索为学习入口，以 FastAPI 业务后端承接账号、组织、课程、作业、内容、学习分析、后台任务与审计治理。它借鉴综合教学平台的课程、班级和教学协作结构，但不以“全面替代”或“全面优于”某一成熟平台作为当前承诺；差异化重点是可视化实验、代码执行追踪、跨学科互动和三角色数据闭环。

当前阶段的作品形态是课程作业 / 设计大赛展示版，目标是在单机环境完整呈现教学创意、交互课程和三角色协同，而不是提前承担真实学校长期运营、公网服务或大规模并发。现有生产化设计与工具保留为后续扩展能力，不作为当前完成条件。

一级产品入口包括：

| 星系 | 定位 | 当前入口 |
| --- | --- | --- |
| 工科试验室 | 数学、物理、化学、算法、生物五大学科与 88 个交互实验 | 主站 SPA |
| 代码空间 | 6 组模块化编程课程、18 个四语言预测/运行/追踪/修正活动 | `codevis/` 独立课程子站 |
| 未来星系 | 6 组跨学科课程、18 个单目标活动、6 个 Canvas 互动与按需 Three.js 代表课 | 主站课程目录与六方向独立子课 |

用户进入星序应用外壳前必须完成账号认证。角色由服务端 Session 权威确定：学生仅进入学习域，教师增加教学管理域，管理员增加全局治理域；前端显示不得替代后端授权。

## 2. 系统组成

```text
浏览器
├── 主站 SPA：index.html + shared/ + pages/
├── 代码空间：codevis/
└── HttpOnly Cookie 会话
          │
          ▼
FastAPI 业务后端：backend/
├── 认证与用户
├── 学校、班级、课程、作业
├── 内容、学习分析与知识快照
├── 告警、后台任务与审计
└── 管理概览与受约束治理
          │
          ▼
SQLite 本地展示环境 / MySQL 后置发布选项

静态交付：Node 开发静态服务 / C++ Release 静态服务
公开入口：Caddy 将 /api/* 转发到 FastAPI，其余静态请求转发到静态服务
```

当前展示版由 `astra-local.ps1` 在 9001 同源提供前端与 API；MySQL、反向代理与四服务部署实现保留为后置工程。技术路径、准确文件、接口、生命周期、启动和维护方法统一见 [`01-开发者手册.md`](01-开发者手册.md)。

## 4. 开发与发布边界

| 范围 | 当前边界 |
| --- | --- |
| 身份与资源 | 浏览器使用 HttpOnly Cookie Session；角色资源在会话确认后按权限加载，前端裁剪不替代服务端授权 |
| 教学与治理 | 三个学习单元共享课程发布、进度和提交权威；学校/班级治理只接受白名单字段、原因与乐观并发，不开放任意 SQL 或表编辑 |
| 学习运行时 | 工科试验室保留经验证与 fail-closed 的实验生命周期边界；代码空间与未来星系使用独立课程活动和按需运行时 |
| 本机验收 | `astra-local.ps1` 在 9001 同源交付前端与 API；该结果只代表 development/本机验收 |
| 当前交付 | `astra-local.ps1` + SQLite + 9001 是课程作业 / 设计大赛展示版的正式验收入口；要求可重复启动和三角色数据对账 |
| 后置发布 | 域名、TLS、secret store、正式 MySQL、备份恢复、日志监控、四服务和回滚证据由 `OPS-001/R6` 保留，但不阻塞 V8.0 展示版 |
| 外部能力 | Webhook、GitHub issue sync、audit anchor、学生 AI 助教、教师 AI 教学助手、AI 维护 / 管理助手和真实 OJ provider 当前均关闭；恢复时必须使用 02 中的独立任务、明确 provider / 权限 / 人工确认边界并完成专项验收 |
