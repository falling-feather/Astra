## 1. 运行方式与环境

| 方式 | 数据与输出 |
| --- | --- |
| 学科主站完整本机版本 | `qianduan/dist` + FastAPI + SQLite，`http://127.0.0.1:9001/` |
| 学科主站前端热更新 | Vite 5173；真实模式的 `/api`、`/labs` 代理到 9001 |
| 学科主站静态演示 | `qianduan/dist-demo`；无真实账号或成绩，刷新重置 |
| 职教动态课堂 | `zhijiao/apps/web/dist` + Fastify；页面 4173、API 3001，见第 8 节 |
| 职教公开导览 | `zhijiao/.local/public-student-demo/dist`；预设访谈、浏览器草稿，无教师提交与评分 |
| 公网业务后端 | 尚未作为本阶段交付；不能把 Pages 当作业务服务器 |

学科主站 Python 使用 3.12+ 和 [requirements.lock](../backend/requirements.lock)。Node/npm 按 [.node-version](../.node-version) 与 [package.json](../package.json) 使用 Node 24.20.0 / npm 11.19.0；该版本满足当前 Windows 递归复制约定。CI 读取同一 Node 配置，不维护另一份版本值。

职教子站是独立 pnpm 工作区；[package.json](../zhijiao/package.json) 当前版本为 `3.0.1`。运行预检要求 Node `>=22.12.0` 和精确的 pnpm `11.9.0`，并非任意 pnpm 11 均可。Windows 启动器还要求 `corepack` 命令可用；不能仅凭 Node 版本推定 Corepack 已安装。根 npm 锁与职教 pnpm 锁分别安装，不能互相替代。

中文文件使用 PowerShell 7 与显式 UTF-8；Python 命令使用 UTF-8 模式。临时文件只放工作区已有临时目录，不在磁盘根创建临时目录。

## 2. 本机完整版本

以下命令均从仓库根目录执行，并以满足上一节环境约束为前提：

```powershell
powershell -ExecutionPolicy Bypass -File .\astra-local.ps1
```

启动器默认在仓库 `.venv` 创建或复用 Python 环境，解析精确 Python，安装锁定依赖、构建正式门户、执行 Alembic 后前台启动 Uvicorn。成功入口为 `http://127.0.0.1:9001/`；停止使用 `Ctrl+C`。准确行为以 [astra-local.ps1](../astra-local.ps1) 为准。首次使用空数据目录并需要管理员时，执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\astra-local.ps1 -BootstrapAdmin
```

数据默认保存在 `%LOCALAPPDATA%/Astra/local-preview`，包含 `astra-local.sqlite3` 与审计盐。`-DataDirectory` 可选择隔离目录；同一数据库的重复进程由实例标识与互斥检查阻止。用户的既有数据库不得因演示失败而删库重建。

| 参数 | 用途与边界 |
| --- | --- |
| `-BootstrapAdmin` | 交互创建首管理员；密码隐藏输入，经当前进程 stdin 交给 API，不写入命令或仓库 |
| `-InitializeDemoData` | 在指定本机 SQLite 通过 API 初始化合成演示数据；公开真实账户数据不属于此用途 |
| `-VirtualEnvironmentPath` | 在仓库外创建/复用受控环境；拒绝仓库内路径、设备命名空间和重解析链接 |
| `-PythonExecutable … -SkipDependencyInstall` | 使用调用方管理的解释器；先做离线锁校验及 pip check，不自动安装 |
| `-Port` | 指定本机端口；同数据库和端口归属检查继续生效 |

两个 Python 选择参数互斥。外置环境需要匹配真实 `sys.prefix`；初始化失败后先检查输出，不将未知环境当作可用后继续迁移。

需要把托管 Python 环境放在仓库外时，可使用以下示例；路径允许 Unicode 和空格，规范化后不得等于仓库根或位于其子目录：

```powershell
$ExternalVenv = Join-Path $env:LOCALAPPDATA "Astra\Python 环境\preview venv"
powershell -ExecutionPolicy Bypass -File .\astra-local.ps1 -VirtualEnvironmentPath "$ExternalVenv"
```

该模式拒绝 Windows device namespace。所选目录及现存祖先、`Scripts/python.exe`、依赖标记和 `Lib/site-packages` 不得经过 junction、symlink、volume mount 或 cloud reparse point。脚本要求 Python 3.12+ 的 `sys.prefix` 精确归属所选目录，依赖锁 SHA 标记保存在该环境内，不创建或修改仓库 `.venv`。

已有调用方自管环境时使用 `-PythonExecutable "<python.exe>" -SkipDependencyInstall`。脚本不会安装依赖或写依赖标记，而是在创建数据目录、审计盐、迁移和初始化之前，用同一解释器执行离线哈希锁 dry-run 与 `pip check`；失败即停止。后续 pip、Alembic、初始化及 Uvicorn 均使用选定的精确 Python。`-BootstrapAdmin` 与 `-InitializeDemoData` 也不能同时使用。

演示初始化器会检查既有合成记录是否漂移，不覆盖已被人工修改的账号、课程或学习事实。保留可用原数据；需要全新演示时明确指定新的隔离目录。合成记录不代表真实课堂证据。

当前 HTTP 服务读取 `qianduan/dist`，不会自动把修改过的 TypeScript 变成新的静态产物。正式验收时重新构建并重启；前端开发使用 Vite。

## 3. 独立前端开发与静态展示

正式前端脚本、构建模式与参数原件见 [qianduan/README.md](../qianduan/README.md)，不在此重复完整命令集。运行入口是 `npm --prefix qianduan run dev` 或显式 `dev:demo`。

`build` 生成真实模式 `dist`；`build:demo` 生成 `dist-demo`。预览演示使用 `preview:demo`，不会继承后端代理。前端请求失败不会自动改用演示数据。

资源包只包括允许公开的文件、三空间资源及许可证；数据库、后端源码、凭据和 UI.pen 不在包中。由 [verify-package.mjs](../qianduan/scripts/verify-package.mjs) 校验入口、资源与来源信息。

## 4. GitHub Pages 发布

源码提交和推送到 main 后，从正式前端执行 [发布流程](../qianduan/README.md#制品与-github-pages)。Astra Pages 基础路径为 `/Astra/`，来源为 `qianduan` 分支根目录。

[publish-demo.mjs](../qianduan/scripts/publish-demo.mjs) 检查源码与构建来源、远端 main 和分支占用，使用临时 Git 索引创建制品提交，不切换或清空主工作区，不强制覆盖远端。

`build-info.json` 记录模式、基础路径、源提交和来源目录状态。验收须核对 Pages 实际构建、深链、资源路径与角色演示；发布事实记在 03。不要在制品分支手工修改业务代码。

## 5. 后端与迁移

从 `backend/` 运行独立 API：

```powershell
python -X utf8 -m pip install --require-hashes -r requirements.lock
python -X utf8 -m alembic upgrade head
python -X utf8 -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

这个入口只提供 API；正式门户同源联调使用第 2 节。后端配置原件是 [config.py](../backend/app/core/config.py)，接口从 [router.py](../backend/app/api/router.py) 注册。

当前迁移 head 是 `20260916_0064`；以 `alembic heads` 和迁移目录确认实际版本。默认本机 SQLite，已有 MySQL 专项验证不等于生产容量和恢复证明。升级已有重要数据前保留可恢复副本，迁移回退不等于恢复丢失的业务数据。

0064 建立追加式学习、提交、评分与认定记录。升级不推测旧版号或旧满分，不还原已经脱敏的反馈；缺少原满分的历史稿不能直接重新给分。新历史产生后禁止有损降级。旧作业客户端需要升级到带上下文和修订条件的写协议，正式门户已使用 v2；本轮仅验证隔离 SQLite，真实 MySQL 升级与并发仍待阶段验收。

默认关闭教师直接注册、自行建校和旧式直接入班。`ASTRA_ALLOW_LEGACY_LOCAL_BOOTSTRAP` 只在受控本机初始化期间有效，生产环境不能借此提权。Webhook、外部 issue、审计外投、正式源码执行和后台调度不随普通启动隐式开启。

## 7. 故障定位

| 现象 | 先核对 |
| --- | --- |
| 根页面返回“前端尚未构建” | 是否生成真实模式 dist；不能用演示包替代 |
| 修改源码后仍是旧画面 | Vite 与静态产物入口是否混用，是否重建 |
| 9001 被占用 | 实例响应头、数据库和进程归属；不要终止未知进程 |
| Cookie 写入被拒绝 | 页面来源、API 来源与允许列表是否一致 |
| 演示初始化拒绝既有记录 | 是否人工修改过合成样例；保留原库，选新隔离目录 |
| 新课程没有可引用活动 | 核对目录注册、官方活动白名单和前端选项，见 01 第 11 章 |
| 主站职业教育入口无法打开 | 职教 4173 是否已就绪，主站构建时的 `VITE_VOCATIONAL_APP_URL` 是否正确 |
| 联合启动后职教进度似乎消失 | 默认创建新目录；检查终端输出的 `dataDir`，下次复用使用 `-ReuseVocationalData` |
| 职教提示包管理器版本不符 | 在 `zhijiao/` 运行 `corepack pnpm preflight`，须精确匹配 pnpm 11.9.0 |
| AI 助教返回 503 | 主站是否同时设置启用开关与服务端密钥；见第 9 节 |

## 8. 职教子站运行与数据

### 8.1 独立启动与账号

从仓库根目录启动动态课堂：

```powershell
powershell -ExecutionPolicy Bypass -File .\zhijiao\启动职教星云.ps1
```

[启动器](../zhijiao/启动职教星云.ps1) 会准备本地 pnpm shim、执行预检、按 `pnpm-lock.yaml` 安装依赖，再构建和启动 API/Web。就绪后学生入口为 `http://127.0.0.1:4173/`，教师入口为 `http://127.0.0.1:4173/login?role=teacher`；API 为 `http://127.0.0.1:3001/`。Web 通过同源代理访问 `/api` 与 `/health`，停止使用启动终端的 `Ctrl+C`。

| 参数 | 用途与边界 |
| --- | --- |
| `-Role teacher` | 启动后打开教师登录入口；不绕过登录 |
| `-FreshData` | 在 `.local/fresh-runs/<时间与进程标识>` 创建新数据目录，不删除旧目录 |
| `-SkipInstall` | 跳过依赖安装；仅用于现有依赖与锁文件一致时 |
| `-SkipBuild` | 复用已有构建产物；修改源码后应重新构建 |
| `-NoBrowser` | 只启动服务，不自动打开浏览器 |

登录页提供教师 `teacher` 和学生 `student1`、`student2`、`student3`，公开演示密码均为 `Demo2026`，原件见 [demo-login-accounts.ts](../zhijiao/apps/api/src/demo-login-accounts.ts)。这是本机演示身份体系，与主站首管理员、账号和 Cookie 会话独立；不能据此声明已完成公网账号体系。

也可在已提供精确 pnpm 命令的环境中，从 `zhijiao/` 运行：

```powershell
pnpm preflight
pnpm install --frozen-lockfile
pnpm start
```

`pnpm start` 默认复用数据；`pnpm start:fresh` 创建新目录；`pnpm dev` 构建共享包后启动开发 API 与 Vite。职教开发 Web 默认也是 5173，与主站 Vite 相同，同时开发须为其中一个显式选择其他端口。页面入口和端口以启动输出为准。

### 8.2 联合启动与主站入口

已经完成主站首次账号初始化后，从仓库根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-joined-stack.ps1 -ReuseVocationalData
```

[start-joined-stack.ps1](../start-joined-stack.ps1) 分别启动主站 9001 和职教 4173/3001；保留两套服务和数据，不合并 API、账号或数据库。**省略 `-ReuseVocationalData` 时，联合启动器默认向职教传递 `-FreshData`，每次创建新目录。** 此开关复用默认目录或 `DEMO_DATA_DIR` 指定目录，不会自动选择最近一次 fresh 目录；需要接续该次进度时，应把 `DEMO_DATA_DIR` 指向其实际路径。

联合启动还支持 `-AstraPort`、`-VocationalRoot`、`-SkipVocationalInstall`。它不透传主站 `-BootstrapAdmin`、自管 Python 或外置环境等全部参数；需要这些选项时，按第 2 节和 8.1 节分别启动两个进程。

主站职业教育入口通过 [environment.ts](../qianduan/src/services/environment.ts) 的 `VITE_VOCATIONAL_APP_URL` 跳转，默认值为 `http://127.0.0.1:4173/`。修改职教 Web 端口或使用其他地址时，应在构建主站前设置此变量，并重新构建主站；仅改职教端口不会同步改变跳转地址。现有主站 Pages 包也不能自动提供本机职教 API。

| 配置 | `pnpm start` / 启动器行为 |
| --- | --- |
| `DEMO_HOST` | API/Web 共同监听地址，默认 `127.0.0.1` |
| `DEMO_API_PORT` / `DEMO_WEB_PORT` | 默认 3001 / 4173；Web 代理随之设置，端口占用会拒绝启动 |
| `DEMO_DATA_DIR` | 复用模式的数据目录；推荐绝对路径，fresh/smoke 模式另建目录 |
| `WEB_ALLOWED_ORIGINS` | 允许来源列表；启动脚本追加本次 Web 来源 |
| `VITE_API_PROXY_TARGET` | 单独运行职教 Web 时的 `/api`、`/health` 代理目标 |

配置示例见 [zhijiao/.env.example](../zhijiao/.env.example)。启动脚本读取 `zhijiao/.env.local`；其中 `HOST`、`PORT`、`DATA_DIR` 用于直接运行 API，完整演示栈会用上表 `DEMO_*` 计算后覆盖它们。不要把更改 `PORT` 当作更改完整栈端口。

### 8.3 数据与停机备份

| 系统 | 默认位置与内容 |
| --- | --- |
| 学科主站 | `%LOCALAPPDATA%/Astra/local-preview`，包括 `astra-local.sqlite3`、审计盐；可用 `-DataDirectory` 隔离 |
| 职教动态课堂 | `zhijiao/.local/data`；fresh 模式另存 `.local/fresh-runs/`，实际路径由启动输出的 `dataDir` 确认 |
| 职教内容库 | 职教数据目录的 `content-library/`，嵌入式 PGlite；14 张业务表加 1 张迁移记录表 |
| 职教学习记录 | 同一职教数据目录内的 JSON/JSONL、会话事件、选课、世界状态、笔记、作品、评价及 `objects/` 附件等 |
| 职教公开导览 | 当前浏览器的本地记录；不进入上述服务端目录 |

职教 SQL schema 位于 [migrations.ts](../zhijiao/packages/content-store/src/migrations.ts)，文件存储接线位于 [server.ts](../zhijiao/apps/api/src/server.ts)。PGlite 是内嵌 PostgreSQL 运行时，无需单独安装 PostgreSQL 服务；它只承载内容库，不能把所有课堂状态都视为 SQL 表。两套数据分别备份，主站 SQLite 副本不能恢复职教会话，只复制职教内容库也不能恢复全部课堂进度。

职教提供 `pnpm data:backup`、`pnpm data:verify`、`pnpm data:restore`。它们调用已构建的 [data-safety-cli.ts](../zhijiao/apps/api/src/data-safety-cli.ts)，所以先完成正常构建。备份前停止持有同一数据目录的 API；恢复只接受尚不存在的新目标目录。以下示例在 `zhijiao/` 执行，若本次用了 fresh 或自定义目录，替换为实际路径：

```powershell
$VocationalData = (Resolve-Path .\.local\data).Path
$VocationalBackups = Join-Path $env:LOCALAPPDATA "Astra\vocational-backups"
pnpm data:backup --data-dir "$VocationalData" --backup-root "$VocationalBackups"
```

使用备份输出的绝对 `backupPath` 执行 `pnpm data:verify --backup "<备份目录>"`；恢复参数为 `pnpm data:restore --backup "<备份目录>" --target-data-dir "<新目录>"`。后续运行把 `DEMO_DATA_DIR` 指向恢复目录并采用复用模式，不能继续使用 fresh 开关后误认为恢复无效。

### 8.4 公开导览构建与预览

公开导览与动态课堂是不同构建入口。准备好职教依赖后，在 `zhijiao/` 执行：

```powershell
pnpm build:packages
node scripts/build-public-demo.mjs
python -X utf8 -m http.server 4174 --bind 127.0.0.1 --directory .local/public-student-demo/dist
```

访问 `http://127.0.0.1:4174/`；上述预览使用已安装的 Python 标准库静态服务。[build-public-demo.mjs](../zhijiao/scripts/build-public-demo.mjs) 实际生成 `.local/public-student-demo/dist`，包含相对路径资源、课程目录及分课程 JSON。当前 `package.json` 没有专用 `build:public` / `preview:public` 脚本，也没有 `preview-public-demo.mjs`；`@ronggang/web preview` 预览的是动态 Web 的 `dist`，不能替代这里的目录预览。

导览包含蟳埔、榕江、山地景区三个地区的五门课程：社区深度采访、赛事采编、发布与回应、素材与版权、暴雨服务报道。页面提供课程资料、预设人物访谈、当前浏览器内的笔记和作品草稿，以及 Markdown 导出；没有实时模型对话、服务端提交或教师评分。清除浏览器数据会清除导览记录，正式业务数据不应填入公开导览。

### 8.5 分项验证入口

在 `zhijiao/` 按变更范围选择 `pnpm preflight`、`pnpm build`、`pnpm typecheck`、`pnpm test`。服务连通烟测使用 `pnpm start:smoke`，会创建临时数据、检查 API/Web/代理和演示会话，结束后清理本次临时目录；它不证明所有课程或真实模型流程已通过。需要离线验证时，先显式设置 `DEMO_MODEL_PROVIDER=deterministic` 和 `IFLYTEK_MODE=mock`，避免继承已有真实服务配置。

`pnpm check` 是定义中的组合入口；当前快照缺少其 `check:docs` 预期的 `zhijiao/doc` 文档集，也未提供 Playwright 配置与独立端到端套件。不能把脚本存在或其他分项通过写成完整门禁已通过。实际执行结果、缺项和验证环境统一记录在 03。

## 9. 可选 AI 配置与验证边界

### 9.1 学科主站 AI 助教

主站助教由 FastAPI [ai_tutor.py](../backend/app/api/endpoints/ai_tutor.py) 提供，需要已登录用户。默认关闭；仅当启用开关、DeepSeek 提供方和服务端密钥同时满足时才发起模型请求。配置由进程环境或 `backend/.env` 提供，读取规则见 [config.py](../backend/app/core/config.py)，更改后重启 API。

| 配置 | 当前默认与用途 |
| --- | --- |
| `ASTRA_AI_TUTOR_ENABLED` | `false`；启用时设为 `true` |
| `ASTRA_AI_TUTOR_PROVIDER` | `deepseek`，当前支持的提供方 |
| `ASTRA_AI_TUTOR_API_KEY` | 服务端密钥；不写入浏览器 `VITE_*`、源码或公开制品 |
| `ASTRA_AI_TUTOR_BASE_URL` | `https://api.deepseek.com` |
| `ASTRA_AI_TUTOR_MODEL` | 代码默认 `deepseek-chat`；按实际账号可用模型明确配置 |
| `ASTRA_AI_TUTOR_TIMEOUT_SECONDS` | 默认 30，允许 5–120 秒 |

登录后 `GET /api/ai-tutor/config` 返回可用状态，`POST /api/ai-tutor/chat` 未启用时返回 503“学校尚未启用 AI 助教”；上游请求失败或没有可显示回答时返回 502。当前请求使用单次问题与页面上下文，不自动查询课程证据库，也不替代教师评分或学习掌握认定。普通本机启动和静态演示不构成真实模型验收。

联合启动器另有配置桥接：若 `zhijiao/.env.local` 中存在非空 `DEEPSEEK_API_KEY=`，会为主站设置助教启用、DeepSeek 地址及 `deepseek-flash` 模型。该行为不取决于职教的 `MODEL_PROVIDER`，也不自动采用职教自定义模型地址；需要分别控制两站 AI 时，采用独立启动并显式设置各自环境。

### 9.2 职教模型、检索与媒体处理

职教 [model-gateway](../zhijiao/packages/model-gateway/src/config.ts) 支持 `deterministic`、`deepseek`、`iflytek_xingchen`。默认模型为 `deterministic`，讯飞适配器为 `IFLYTEK_MODE=mock`，核心课堂演示不要求真实模型密钥。真实 DeepSeek 需在服务端设置 `MODEL_PROVIDER=deepseek`、`DEEPSEEK_API_KEY` 和所用模型等配置；完整栈若设置 `DEMO_MODEL_PROVIDER`，其优先级高于 `MODEL_PROVIDER`。

`DEEPSEEK_LIVE_SMOKE` 是专门测试的开关，不是业务联网总开关；即使值为 0，已选择真实提供方的业务请求仍可能访问外部服务。`SHOWCASE_DETERMINISTIC_STRUCTURED=1` 会让部分结构化智能体继续使用确定性实现，不能凭健康检查中的提供方名称宣称全部智能体都调用了真实模型。模型输出仍需经过人物知识范围、结构校验和世界规则；需要教师确认的状态变更由教师门控承认。

本地材料解析、向量检索与媒体能力需要额外环境，不包含在 pnpm 安装内。[setup-ai025-runtime.ps1](../zhijiao/scripts/setup-ai025-runtime.ps1) 和 [setup-be007-runtime.ps1](../zhijiao/scripts/setup-be007-runtime.ps1) 默认建立 Python 3.11 的独立工作环境；模型资源可能首次下载。解释器路径可用 `RONGGANG_AI025_PYTHON`、`RONGGANG_CONTENT_PYTHON` 指定。仅提供模型 API Key 不等于完成材料导入、授权、切片和向量索引。

当前场景材料覆盖五门课程，但人物采访的内容库检索接线仍以蟳埔课程作用域为入口，不能描述为所有课程均已完成通用 RAG。`pnpm content:prepare` 依赖既有 `资料/04-职业教育依据/` 中的指定 PDF 和正在运行的动态站，会执行导入与索引，不属于无条件的首次启动步骤。真实模型、向量工作环境、媒体转写/理解和教师评价应分别验证；没有配置图像模型及对应处理依赖时，不把文本降级结果宣称为真实多模态观察。
