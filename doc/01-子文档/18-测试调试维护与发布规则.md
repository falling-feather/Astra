## 14. 维护指南

### 14.1 常见任务

| 任务         | 操作                                             |
| ------------ | ------------------------------------------------ |
| 发现既有实验问题 | 先在 `02-更新规划.md` 记录证据、文件和回退方式，未经负责人批准不得修改 |
| 新增实验     | 从 `tools/templates/new-experiment/` 复制新 key、新路由、新 owner 和独立样式骨架，不改既有实验 |
| 修改导航     | 编辑 `index.html` 的 `<nav>` + `config.js` |
| 调整主题色   | 编辑 `tokens.css`                              |
| 新增学科     | 见 §14.2                                        |

### 14.2 新增学科

1. 在 `CONFIG.pages` 和 `CONFIG.experiments` 中添加学科配置
2. 在 `index.html` 中添加导航项 + 页面 `<section>`
3. 创建 `pages/新学科/` 目录
4. 在首页添加卫星（HTML + CSS + JS 轨道配置）
5. 在 `SatelliteSystem.orbits` 中添加轨道半径、倾角、周期与相位数据
6. 在 `home.css` 中添加卫星样式
7. 更新 `selectModule()` 中的颜色映射

### 14.3 调试技巧

- **路由问题**：在控制台输入 `Router.currentPage` 查看当前页面
- **模块选择器**：`ModuleSelector.activeModule` 查看当前展开的模块
- **Canvas 问题**：在实验对象中添加临时 `console.log` 或使用 Canvas Inspector 浏览器扩展
- **动画问题**：GSAP DevTools（`gsap.globalTimeline`）
- **加载问题**：先检查 `AstraPageRegistry.scriptFor(page)` / `Router.galaxySupportScripts`、`noDeferred=1` 降级路径和控制台 Long Task；若页面 DOM 读取也超时，优先排查 `MutationObserver` 回调、无条件 DOM 重写和 RAF/timeout 循环

### 14.5 UI-015 浏览器验收口径

公开导览必须从同源本地入口验收，不能用静态服务器的 `/api/users/me` 404 代替真实未登录 401。当前工作区候选使用 `20260823v815PublicGuideP1`，已完成以下检查：

- 1440×900 与 390×844 均覆盖首屏、教学闭环、三星系目录、两门重点课程和账号入口；
- 目录显示的 `88/18/18` 来自 `AstraLearningActivityCatalog.verify()`，不是页面硬编码；
- 导航、账号 tab 与主要动作不小于 44px，移动端无横向溢出；
- `prefers-reduced-motion: reduce` 下按钮动画关闭，导览滚动从 `smooth` 降为 `auto`；
- 登录、注册、重置密码切换保留各自字段，未提交任何真实凭据；
- 同源页面的 console warning/error 为 0，账号入口不显示伪错误。

### 14.6 本地预览锁文件摘要

`astra-local.ps1` 的 `Get-AstraFileSha256` 使用 .NET `SHA256` 和只读文件流计算 `backend/requirements.lock` 摘要。这里禁止重新依赖 `Get-FileHash`：本地预览 Python 选择合同会收紧子进程 `PATH`，PowerShell 模块自动加载并不可靠。外置虚拟环境创建完成后，版本探测、`sys.prefix` 校验、依赖安装、Alembic、演示数据初始化和 Uvicorn 必须继续使用同一个已解析的 `RuntimePython`。

### 14.7 既有实验还原与保护性回归

2026-08-24 起，当前 124 项既有实验默认进入冻结保护。测试的职责是证明它们没有被新增平台或课程包装破坏，不是借回归机会继续重绘页面。

还原验收至少包含：

1. 注册表中的既有 activity key、路由和 owner 数量不减少；
2. 被否决的课程旅程文本、额外星图入口、演示课程种子、图稿和专属合同不存在；
3. 代表实验通过规范 hash 进入；进入实验工作台后能直接看到核心画面和主要控制；
4. 至少完成一次参数操作、一次暂停/重置或节点切换、一次离开和再次进入；
5. 桌面与 390×844 均无新增横向溢出、遮罩阻断或 console warning/error；
6. 公共缓存代际使用 `20260824v816ExperimentRestoreP2`，避免既有浏览器继续命中被否决页面或中间恢复字节；
7. 任何知识性纠错或阻断修复必须带负责人批准记录，测试报告要说明精确受保护文件。

浏览器代表样本不能被描述为“124 项全部视觉验收”。全部 124 项只做身份、路由和资源的自动化保护；人工浏览器结论必须准确列出实际操作过的实验和视口。

本轮真实代表样本为：

| `#physics/mechanics` | 重力值更新、暂停/继续、画布拖拽发射、无课程证据壳 | 控件单列、画布 318×320、拖拽发射、根级溢出 0 | 通过；`#physics` 目录中的历史“学习目标/先预测”卡片文案不属于本轮还原，等待负责人决定是否允许外层清理 |

### 15.1 当前开发口径

- 当前活动集成分支为 `主开发`，只由主开发单线处理；不自动恢复工作组或新增工作树。实验还原基线为 `主开发@6c3fd93 / V8.1.6`，新增模板为 `主开发@6993444 / V8.2.0`；V8.1.0—V8.1.5 是未提交工作区候选。V8.2.1 `EXT-02` 只增加只读注册检查，后续严格按 `EXT-03` 起单任务推进。
- V7.7.2 已从 `codex/fe-v7.7-evidence@ac200c8` 集成到 `主开发`：只包含共享证据 core/catalog/status、两个非 Future 代表活动、角色 recovery / aggregate 回读和 ModuleSelector 清理事务修复；Future 运行接线、其余课程及真实 9001 / SQLite / 跨标签 / 三角色 QA-014 A03a 仍未完成。
- 当前目标是毕业设计 / 多媒体与教学工具竞赛的本地展示版：优先新增独立精品实验、改善实验外的学生/教师发现与组织路径，并完成稳定演示包。真实 MySQL、公网发布、隔离 runner、压力测试、真实课堂和 AI 能力不得成为当前隐性阻塞项；既有实验不得再为展示课程能力而被重写。
- 当前没有 AI 助教或智能治理运行能力。恢复 AI-001—AI-003 时必须分别处理学生、教师和维护 / 管理场景，禁止把同一个聊天框冒充三类能力；任何权威教学或治理写入继续要求人工确认、领域授权和审计。
- 业务 API、登录、课程、作业、学情和管理端能力优先进入 `backend/`，不要继续扩展 C++ 占位 API。
- 班级加入长期保留 direct join 与 join request 两条路径：`POST /api/classes/{id}/join` 用于学生直接加入、admin 治理、导入/邀请码或旧 UI 兼容；teacher 角色的普通教师加入必须走 `POST /api/classes/{id}/join-requests` 并由本班 active teacher 或 admin 审批；新 UI 应按场景选择入口，不应暗示审批流是唯一方式，也不应让普通教师绕过审批成为班级 teacher。
- 班级成员治理以保留历史为前提：`GET /api/classes/{id}/members` 只允许全局 admin 或该班 active teacher membership 读取；学生“移除”写为 membership 软停用，教师可通过 `POST /api/classes/{id}/students/batch-import` 逐项导入 active 同校学生，通过 `POST /api/classes/{id}/students/{membership_id}/transfer` 在同时拥有源班和目标班 teacher scope 时完成同校转班。teacher membership 仍只允许全局 admin 治理且不能禁用最后一个 active teacher；监护人/联系方式档案和正式邀请模型另行设计。
- 学校、班级、课程范围判断优先复用 `app.services.access_control`。课程 owner 转让仍只允许 current owner 或全局 admin；课程协作者支持 `editor/content_editor/assessment_editor/viewer` 与 owner/admin 批量 upsert，分别约束结构、作业/评估、积分规则和只读能力，但任何课程角色都不会自动授予班级成员、挂课、提交、评分或学情权限。作业通过 `audience_mode` 与 `AssignmentClassPolicy` 按班级覆盖 assigned、状态、截止时间和积分规则；班级策略写入同时要求课程编辑能力与目标班级 active teacher scope。外部 issue 只做管理员显式出站同步，本地 `BugRecord` 是权威源，任何入站/双向覆盖必须另行设计和审计。
- SQLite 性能报告只用于快速合同检查；MySQL `EXPLAIN ANALYZE`、DDL、锁等待和 worker/API 并发必须在目标数据量与隔离环境中复跑，并与 `03-发布历史.md` 的 V6.6.61 基线比较。worker 推荐独立服务，不能用应用层自动重试掩盖写事务结果不确定性。
- 每轮完成后，全部版本与验证证据统一写入 `03-发布历史.md`；规划文档只保留仍影响下一步决策的事项。
