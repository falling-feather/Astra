## 13. 构建与部署

### 13.1 开发环境

Windows 本机功能验收优先使用根目录单入口：

```powershell
powershell -ExecutionPolicy Bypass -File .\astra-local.ps1
```

它创建/复用 `.venv`，严格消费 `backend/requirements.lock`，迁移本机 SQLite，并在 `http://127.0.0.1:9001/` 同源运行 `app.local_preview:app`。该应用复用全部现有 API，只为 `pages/shared/UI/codevis` 和三个审核过的根文件增加静态白名单；其他仓库文件不能通过 HTTP 读取。数据目录 hash 绑定并发互斥与实例识别，首页 same-origin-only 标记使统一 API client 拒绝旧跨端口地址；当前缓存代际为 `20260718v7435QaCloseoutP0`。`-BootstrapAdmin` 只在本机 development + SQLite 下通过隐藏输入和 stdin 调用权威 bootstrap API。三角色证明只能通过成对的临时 `ASTRA_QA_ADMIN_USERNAME`/`ASTRA_QA_ADMIN_PASSWORD` 登录该预置账号，不能重新打开运行时 bootstrap，凭据也不得进入报告。脚本不生成 Windows 服务、TLS、MySQL 或 R6 evidence，也不修改 `deploy.ps1`。

运行时选择有三种互斥口径：

1. 不传新增参数：保持一键入口，在仓库 `.venv` 创建/复用 Python 3.12+，按锁文件 SHA 决定是否用 `--require-hashes` 安装。
2. `-VirtualEnvironmentPath "<仓库外目录>"`：规范化后拒绝仓库根目录及其所有子目录和 Windows device namespace；外置目录及其现存祖先、`Scripts/python.exe`、依赖标记和 `Lib/site-packages` 均不得经过 junction、symlink、volume mount 或 cloud reparse point。创建后还须确认解释器的 `sys.prefix` 精确等于所选 venv，才在其中安装哈希锁依赖并保存 `.astra-requirements.sha256`；不创建或修改仓库 `.venv`。
3. `-PythonExecutable "<python.exe>" -SkipDependencyInstall`：调用方自管模式，与外置 venv 参数互斥。可执行文件必须精确解析为 PowerShell `Application` 且为 Python 3.12+。启动器不安装依赖、不写标记，而是先通过该解释器执行 `pip --isolated --disable-pip-version-check --no-cache-dir install --dry-run --no-index --require-hashes -r backend/requirements.lock`，再执行 `pip --isolated check`。

外置 / 自管路径允许 Unicode 与空格，但调用时必须保持为单个引号参数。自管模式任一只读校验失败时，数据目录、审计盐、环境变量、Alembic、bootstrap、演示初始化与 Uvicorn 都不会发生；成功后所有 pip、迁移、初始化和前台服务也都通过最终解析的同一 `$RuntimePython` 执行，不使用激活脚本、`uvicorn.exe`、裸 Python、链接或环境复制绕过。reparse 检查是启动时失败关闭门禁，不承诺抵御并发替换、SUBST 或充当系统安全隔离；前台与 `Ctrl+C` 生命周期、数据目录 mutex 和初始化顺序保持不变。

`-InitializeDemoData` 是本地预览专用的 API-only 编排入口：

```powershell
powershell -ExecutionPolicy Bypass -File .\astra-local.ps1 -InitializeDemoData -DataDirectory "$env:TEMP\astra-demo-v7919-fresh"
```

它在启动 Uvicorn 前通过 `create_app()` 的 ASGI HTTP 边界调用现有认证、学校/班级、课程/单元、发布计划、学习证据、作业/提交和审计 API，建立固定的 `admin/teacher/student`、14 门课程与 42 个单元。初始化器只接受本机 development + SQLite + `127.0.0.1` 环境；首次生成的强密码仅在终端显示一次，既有账号重跑时使用隐藏输入校验，不保存、不回显到报告或日志。所有既有 canonical 课程会在任何 catalog 创建前完成全局只读预检；发布态、单元、附件、计划、规则、激活或唯一班级绑定发生漂移时直接失败关闭。第五轮独立复审已确认连续三次执行不增殖业务对象或非登录审计，混合“既有 physics + 其余 fresh”反例也会在新增 catalog 前退出。DATA-002 只扩展 `DEMO_ASSIGNMENTS`：`control-flow.loop-boundary` 同时回读一份 `submitted`、未评分且无反馈的合成作业和真实 `runner_unavailable` 代码提交，原 physics graded 与 humanities pending 样例保持不变；通用 `DEMO_ASSIGNMENTS` 循环继续直接消费声明。

DATA-003 由 `backend/scripts/demo_evidence_profiles.py` 统一声明六门代表课的 `producer_mode`、`course_fact_status` 和确定性 payload 构造，`demo_data_manifest.py` 只通过 open activity key 绑定该唯一 profile，`initialize_demo_data.py` 不再从课程自然语言或 payload 内容猜测模式。`physics.mechanics` 使用 `frontend_precise / precise`，预测、两档受控观察、修订严格复用当前物理页 producer，第三次尝试只重放既有 `e=0.40` 形状；`control-flow.loop-boundary` 使用 `frontend_shallow / shallow`，只生成当前浏览器预检、旧 `runner_unavailable`、正式提交回执和代码修订形状，不生成未来 trace。数学、调试、工程、人文统一使用 `generic_lifecycle_fallback / unavailable`，即使服务端派生 completed，也不在报告中声明课程专属事实。每课报告显式包含上述两字段及 `fixture_provenance=deterministic_synthetic_not_browser_capture`；所有数值和动作都是本地确定性合成 fixture，不是浏览器实测或真实学生掌握证据。初始化器继续不直接访问模型、迁移、数据库表或 SQL。

学习事件的 `client_event_id` 与 payload 指纹继续一对一绑定；已经由 DATA-001 / DATA-002 旧通用 payload 初始化过的目录不会被 DATA-003 原地改写，而会按既有幂等冲突门禁失败关闭。需要新 producer profile 时必须停止旧实例并使用新的显式 `DataDirectory`，不得直接编辑 SQLite 或删除旧事件。

Node 质量工具固定使用 Node 22.20.0、npm 10.9.3 和 lockfile v3。`npm ci` 必须禁用安装脚本，避免 Playwright 在依赖安装阶段下载或执行未审查的浏览器产物；浏览器证明使用目标机器已批准的 Edge/Chrome：

```bash
npm ci --ignore-scripts
node tools/tests/learning-evidence-contract.cjs
npm test
```

`npm test` 先通过 Git 跟踪清单对所有 JS/CJS/MJS 执行 `node --check`，再运行统一契约入口。Node/npm/Playwright 版本升级必须在独立依赖变更中同步 `.node-version`、`package.json`、`package-lock.json`、CI 和验证证据；不得手改 lock integrity，也不得重新引入工作区外部 `NODE_PATH` 作为正式依赖来源。

业务后端依赖安装必须消费已审查的哈希锁，不能直接从宽范围 `requirements.txt` 安装：

```bash
python -m pip install --require-hashes -r backend/requirements.lock
```

`backend/requirements.txt` 只作为直接依赖约束输入。依赖更新须独立审查，固定使用 uv 0.10.6、Python 3.12 通用解析和显式软件发布日期截止线；更新后必须同时提交约束与锁差异：

```bash
python -m pip install uv==0.10.6
python backend/scripts/compile_requirements_lock.py --exclude-newer YYYY-MM-DD
python backend/scripts/compile_requirements_lock.py --check
```

CI 使用 `--require-hashes` 安装并重新解析校验锁内容；改变 uv 版本、Python 解析目标或截止线都属于依赖升级的一部分，不能混入普通功能提交。

```bash
# 静态页面单独调试 1: 审核白名单 Node 开发服务器
node server/dev-static-server.mjs --port 8766

# 静态页面单独调试 2: VS Code Live Server 插件
# 右键 index.html → Open with Live Server

# Release 静态服务调试: C++ 服务器（需要 CMake + C++ 编译器）
cd server
cmake -B build -S .
cmake --build build --config Release
./build/Release/englab_server.exe -p 8080 -r ..
```

### 13.2 展示后生产部署（保留方案）

本节记录已经存在的目标发布工具和恢复方案，不描述当前已上线状态，也不属于 V8.0 本地展示版退出条件。用户明确恢复公网发布任务后，可在目标环境采用双服务方案：C++ 服务器承载静态站和历史 fallback，Python FastAPI 承载 `/api/*` 业务接口；反向代理将 `/*` 分流到 C++ 静态服务 `:910`，将 `/api/*` 分流到 FastAPI `:8000`。FastAPI 应只监听 `127.0.0.1` 或内网地址，不直接开放公网端口。

#### Windows 云服务器受控服务包

```powershell
# 先从官方来源获取并复核 WinSW/Caddy，再传入合格的 Release C++ 产物。
.\deploy.ps1 `
  -WinSwPath C:\staging\verified\WinSW-x64.exe `
  -StaticExecutable C:\staging\build\englab_server.exe `
  -CaddyExecutable C:\staging\verified\caddy.exe `
  -OutputDir C:\englab\service-bundle `
  -SecretStorePath C:\englab\secrets\astra-staging.dpapi `
  -PublicOrigin $PublicOrigin
```

密钥文件须先由 `python -m scripts.windows_dpapi_secret_store seal --output <path> --service-account "NT AUTHORITY\LocalService"` 从 stdin 创建；真实 JSON 不得写进命令历史或仓库。`$PublicOrigin` 必须是实际分配的精确 HTTPS origin。`deploy.ps1` 只生成 `EngLab/AstraApi/AstraWorker/AstraProxy` 四服务定义、回环 Caddyfile、hash 和可逆命令，不联网下载、不开放端口、不安装或启动服务；临时 bootstrap 仅在初始化验收时显式 `-EnableAdminBootstrap`，完成后必须重新生成关闭版本。审查、ACL/TLS 和安装顺序以 04 号文档为准。

详见 [04-部署指南.md](../04-部署指南.md) 获取完整部署指南，包括：

- 防火墙 & 安全组配置
- 运维命令（启动/停止/更新）
- 常见问题排查

#### 其他部署方式

- **GitHub Pages**：直接推送到 `gh-pages` 分支（不含 C++ 后端）
- **Vercel / Netlify**：连接仓库自动部署前端
- **Nginx / IIS / Caddy**：作为公网反向代理，静态路径指向 C++ 服务，`/api/*` 指向 FastAPI
