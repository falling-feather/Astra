### 18.1 系统全貌

星序由主站 SPA、代码空间子站、FastAPI 业务后端、数据库和静态交付服务组成。浏览器先通过 `/api/users/me` 确认服务端 Session，再启动 Router；学生、教师和管理员的导航、section 与受保护脚本按权威角色裁剪。

```text
主站 index.html / shared / pages ──┐
代码空间 codevis ──────────────────┼──> 浏览器 + HttpOnly Cookie
                                   │             │
                                   │             ▼
Node/C++ 静态服务 <────────────────┘      FastAPI backend
                                                  │
                                SQLite 本地展示 / MySQL 后置发布
```

#### 18.2.1 权威学习证据合同

新合同统一挂在 `/api/learning-evidence`，只接受服务端 Session/Bearer 既有认证边界：

| 能力 | 接口 | 权限与结果 |
| --- | --- | --- |
| 完成规则 | `POST/GET /rules`、`GET /rules/activation`、`POST /rules/{rule_id}/activate` | owner、`assessment_editor` 或 admin 可创建不可变版本；draft 规则可预置本课程未来活动，但激活时 activity scope 必须与全部当前 published 单元精确相等，并使用 course edit scope、`expected_revision` CAS 和可选班级 `expected_plan_version` 绑定；activation state 返回当前 revision、active rule 与各 active class 的有效 pin；后续纯发布调整继承最近一次绑定，直至新计划版本追加新绑定 |
| 学习事实 | `POST /events`、`POST /events/batch` | 学生只能追加 v1 `started/predicted/attempted/corrected/explained`；服务端持久化 `event_schema_version=1`，客户端不能指定；单项结果为 `accepted/duplicate/rejected/conflict` |
| 教师纠错 | `POST /events/{event_id}/corrections` | 本班教师或 admin 追加独立行政纠错事实；新纠错与学生/受信写入共用发布锁，目标当前 effective access 必须为 open；资源后来 hidden/locked/archived 后，本人精确旧键仍只返回最小 duplicate 回执；原事件不更新、不删除，同一目标只接受一个行政纠错 |
| 教师逐学生证据发现 | `GET /classes/{class_id}/courses/{course_id}/events?subject_user_id=&activity_key=&event_type=&limit=&offset=` | 本班 active teacher 或全局 admin 在精确 `class + course + subject` 范围内读取稳定倒序分页，`limit` 为 1—100、`offset` 为 0—100000；学生、外班教师、未挂班与跨校范围 fail closed。响应保留 learner / trusted-assessment 外层事实、内部纠错用 `event_id` 与纠错关联 ID，并把 `activity_key + event_schema_version + event_type + exact leaf path` 交给纯投影模块。schema v1 当前仅 `physics.mechanics` 与现有浅层 `control-flow.loop-boundary` 可产生最多 12 个固定中文 facts；其余四门、其他 activity、未知 schema/event 固定为空 facts 且 `truncated=true`。源码、开放文本、原始枚举、source/ref/revision/hash/token、未知 nested raw 与原始 evidence JSON 均不返回 |
| 学生恢复 | `GET /me/recovery?class_id=&course_id=` | 返回当前班级发布计划所绑定规则版本下的可见活动投影；只有 effective access 为 `open` 的最后位置及活动项才返回可执行续学游标，locked 顶层 `resume=null` 且活动 `resume_cursor={}`，hidden 活动与游标都不回读 |
| 教师聚合与修复 | `GET /classes/{class_id}/courses/{course_id}/aggregate`、`POST .../rebuild` | 本班教师或 admin 读取当前 bound rule 明确定义的稳定 activity scope（hidden 对教师仍可见，非规则或未发布单元不进入 active 聚合），或从 append-only 事实重建活动/续学投影 |

维护不变量：

- `client_event_id` 与规范化请求 SHA-256 共同实现精确幂等；相同 actor/subject 与相同载荷返回不含课程内容元数据的最小旧回执，换 actor/subject 返回 `403`，同键异载荷返回 `409`。
- 所有学习证据写命令 DTO 都拒绝未知字段。外部 `client_event_id` 必须以 ASCII 字母或数字开头；服务端规则派生使用客户端不能构造的 `@rule:` 保留命名空间，命中既有内部键时仍逐项核对 producer、request hash、subject/scope、rule/outcome 与 source IDs，不一致固定 `409`。
- `course_release_write_gate` 承载学生、OJ、提交、legacy event 和学习证据共用写门禁；实际锁序为 `school → course → class → membership/permission → course-class → unit → plan/assignment policy → binding/rule → ledger/projection`，release-plan PATCH 使用共享的 `school → class → course-class → plan` 子序列。两者先在 school 行序列化，且学生门禁在成员重验后先锁 course-class、再锁 unit/plan。hidden、locked、archived、未来时间、旧规则或班级/课程/活动不匹配均拒绝。事件、规则派生结果和投影在同一事务提交，提交成功后恢复/聚合读取立即可见。
- `completed/transferred` 只由规则服务或内部受信评测入口生成；`transferred` 只表示真实教学迁移任务。教师行政纠错使用 `administrative_correction`，不与学生的 `corrected` 混用。
- v1 顶层事实字段被冻结为：`started` 仅允许可选 `cursor`；`predicted` 必须有非空 `prediction`；`attempted` 必须有 `operation`，可选 `reported_correct/cursor`；`corrected` 必须有非空 `correction`；`explained` 必须有非空 `artifact`。各类型除列出的字段外一律 `422`，全部 evidence 使用有限数值、有效 Unicode scalar 的严格 JSON 且最多 16 KiB；全局校验错误回显同样保证可 UTF-8 编码。`occurred_at` 必须带时区、可安全规范化为 UTC、位于 SQLite/MySQL 共同可表示的 UTC 1000—9999 年范围且不超过服务端未来 5 分钟。`reported_correct` 只是学习者自报，不进入权威完成或教师判断。
- `teacher_evidence_facts.py` 是无 DB、endpoint、schema 或 model 副作用的教师课程事实 owner。facts 键保持已登记的 exact leaf path，值由服务端生成固定中文展示串；字符串只做 exact enum 比较而不回显原值，数值拒绝布尔、非有限、越界和超精度。组合叶必须整组合法才投影，未知 / 多余叶只置 `truncated=true` 且不能挤掉表序中的既有事实。力学只校验 `trial↔e`、固定预设和 `h/H↔h/200` 内部一致，不用理论 `e²` 重判页面实测；循环只投影当前浅层 producer，运行失败的 `reported_correct=false` 仅校验形状且不显示“未匹配”，正式 judge 只表示收到响应。未来 trace、accepted、runner、completed 和其余四课事实均不得合成。
- `completed` 规则不能退化为 started/访问即完成或单次自报正确即完成：每个活动至少要求两个不同事实类型，或至少两次过程 attempt；`minimum_correct_attempts` 在 v1 必须为 0，权威正确性只能由受信评测产生。规则派生 `transferred` 至少要求 `explained` artifact。
- `minimum_attempts` 与单个派生事实的最小 witness 均以 100 条为硬上限；规则派生事件只引用满足条件的确定最小 witness，不把同活动的无关预测或超额尝试并入来源。纠正无关事实不改变完成；纠正 witness 后若其余事实仍满足规则，服务端追加新的派生事实并重建投影，旧派生事实保留。
- 0051 不把旧 `LearningEvent.complete` 升级成新证据；它只对迁移执行前已经存在的历史行回填 `legacy_access_entitlements`。升级后 `/api/learning-events` 的新 `event_type=complete` 固定返回 `409`，既不写旧事件也不生成权益。权益表只由发布/先修门禁查询，不进入新活动投影、完成率、教师聚合或 `transferred` 统计。
- `/api/learning-events`、`/api/knowledge` 与旧课程进度矩阵仍是兼容接口；`/api/progress` 也只保留兼容响应外壳，但其中完成数/率已严格读取当前班级绑定规则下 published、非 hidden 的权威投影（locked 仍属于应完成范围），不再从旧事件推导。新调用方不得从旧 `complete` 或访问次数推断掌握。
- BE-006 尚未提供单活动事件总量配额或主体速率限制；投影 / 纠错重建仍读取 scope 内 append-only 事件全量。100 条规则 / witness 上限只约束单次派生来源，并非总账配额。展示版保持现有限制且不提高上限；真实规模配额、归档与 MySQL 执行计划属于后置 BE-010。

下游接入限制：

- 0051 只建表和迁移历史访问权益，不会为现有课程自动生成内容规则。FE-012/CONTENT-001 必须在课程 published 单元稳定后，由 owner、`assessment_editor` 或 admin 受控创建首个完整规则，再由 course editor 以当前 activation revision 和班级 plan version 激活/绑定；在此之前学习事实写入、恢复和教师聚合必须诚实返回 `rule_binding_missing` 等 `409`/空状态，禁止伪造进度。
- 后端已提供逐学生证据发现与追加式纠错的 `event_id → correction → corrected_by_event_id` 回读闭环，课程 facts 只认 27 号冻结契约中的力学与循环当前 producer。V7.8.5 教师 UI 只渲染服务端 facts，不读取原始 evidence、不在浏览器重做 allowlist，也不把空 facts / `truncated` 推断为答错；其余课程显示固定降级说明。页面用短期 opaque token 映射内部事件 ID，已纠正及 hidden / locked 历史不提供新增纠错，筛选和翻页始终携带当前 `class + course + subject`，写入未知结果后重新读取同一权威页且不盲重发。
- 教师自然工作流只在明确选择唯一班级与课程且课程已挂班后运行；切学校、班级或课程会同步中止旧 generation，并在新请求前清除提交源码、判题尝试、证据分页、对话框和焦点返回点。桌面使用学生 × 可见分块语义表，移动端使用逐学生 `<details>`，hidden 只显示数量且不暴露名称或键。原生 dialog 在打开时暂停进度轮询，捕获 Escape / Tab，关闭、确认或销毁时对称释放监听并精确返焦。
- 课程挂接状态由同一教师证据 owner 消费，不进入通用 scope key 或纠错 fence。同一 `base + class + course` 下 false→true 只通过既有 timer 合并刷新；true→false 先标记已消费状态，再执行 fail-closed 清理，因此不会把旧学生、证据、源码、纠错或对话框残留到未挂接课程，也不会在 false 状态读取私有 progress / aggregate。

V7.7.2 前端首批稳定实现边界：

- `app-session.js` 按需加载 `learning-evidence-loader.js`，并把当前脚本的 `v` 查询值显式复制到 loader URL；loader 再把同一值传播到 queue、client、status、catalog 与 activity 动态脚本。显式登录与注册流程必须先完成本地 authority 清理，再发送会建立 Session 的登录请求，成功后以一次性 fresh proof 配置新身份。退出、运行中 401 与账号 / 角色变化先写入同源、固定值且不含身份 / 原因 / 凭据的 transient marker，再推进不含身份信息、清理成功后仍保留的持久 clear epoch，随后物理清空排队命令；两者复用 `localStorage` 与同源 Cookie 两个通道。合法 BroadcastChannel / storage set 通知直接撤销活动标签的 authority，`pagehide` 关闭通知通道，`pageshow` 通过 epoch 变化补回隐藏期间错过的清理。IndexedDB、marker / epoch 持久化或 marker 删除失败时应用保持锁定且不重载，fresh proof 也不能越过失败 latch，只有显式重试物理清理成功后才能重新配置身份。

#### 18.2.2 管理员课程状态治理

`PATCH /api/courses/{course_id}/status` 仅允许全局管理员调用，请求体严格为 `expected_status + status + reason`，未知字段固定 `422`。状态转换只允许 `draft → published/archived`、`published → draft/archived`、`archived → draft`；stale、no-op 和 `archived → published` 均返回 `409`。

DTO 与 endpoint 分别由 `schemas/course_status.py`、`api/endpoints/course_status.py` 持有，并由 `api/router.py` 在 `/courses` 注册；冻结 `api/endpoints/courses.py`、`schemas/course.py` 不增长。写入顺序固定为 `ADMIN_AUTHORITY_LOCK → school → course → lock_active_admin`，锁后重新读取并确认 actor 仍是 active global admin，再执行状态 compare-and-swap。当前单进程 SQLite 展示路径使用同领域事务锁串行化竞争写入，并把残余 `database locked/busy` 归一为 `409`，所以同一 `expected_status` 的并发请求只能产生一条成功审计。成功响应返回提交后的 `CourseRead`，以及 active 挂接班级、课程单元和作业计数；审计动作固定为 `course.status.patch`，快照保存 `before/after/reason/impact`。接口不接受标题、摘要、owner 或其他课程字段，且不新增迁移。

#### 18.2.3 学生单元访问处置

`GET /api/courses/{course_id}/unit-access?class_id=&activity_key=` 只允许 student 调用。服务先按既有学校、成员关系、挂班和 published 课程语义确认学生对精确 `class + course` 有权，再以最长 120 字符、规范小写分段格式的 `activity_key` 做 exact match，并复用 `resolve_student_course_class`、`get_plan_for_unit` 与 `effective_unit_access` 计算当前发布态。

已授权范围内固定返回两个字段：open 为 `{"available":true,"error_code":null}`，hidden / locked / missing 分别返回 `activity_hidden`、`activity_locked`、`course_unit_missing` 且 HTTP 状态均为 `200`。响应不返回单元 ID、标题、正文、slug、发布计划、锁定原因、其他 activity key 或目录；未登录、非学生、未入班、跨班、跨校、draft / archived 课程和 inactive school 继续沿用 `401/403`，非法 `class_id` 或 activity key 为 `422`。同一课程内 activity key 多匹配、目标 plan 缺失、目标关联不一致或未知发布态固定失败关闭为 `409`；无关 plan 漂移不阻断目标读取。正式 schema 的唯一约束阻止正常写入产生重复 plan，运行时不承诺识别绕过约束注入的重复 plan 行。

该能力由独立 schema / endpoint / service 持有，router 只在 `/courses` 注册；冻结 `api/endpoints/courses.py`、`schemas/course.py`、模型与迁移均不变化，也不产生写事务、锁或审计。现有学生 units 列表仍隐藏 hidden 单元；该处置接口只为已知 deep-link 分类提供最小结果，不扩张为目录发现。V7.7.22 前端集成只在 `/units` 精确零匹配后消费该结果，并以严格 DTO、同一取消信号和固定诊断失败关闭；仍需真实浏览器验收，不能把代码 / 合同通过写成 deep-link 产品闭环已经交付。

### 18.4 扩展与维护边界

- V7.6 新业务必须遵守 [`24-V7.6全栈模块边界契约.md`](../02-子文档/24-V7.6全栈模块边界契约.md)：页面 owner → 共享领域客户端 → `AstraApiClient` → endpoint → service → model/database。冻结巨型文件只减不增；页面不得直连学习证据 API，endpoint 不得新增 ORM 直连，底层不得反向导入 API。能力名称和状态只由 `AstraProductCapabilities` 定义；V7.7.2 仅由共享 loader / client 消费首批证据能力，页面不得绕过 owner。
- 新增主站页面前先在 [`02-更新规划.md`](../02-更新规划.md) 建立任务，再同步 `AstraPageRegistry`、DOM 导航身份、脚本/钩子、HTTP fallback、Service Worker 和契约；角色权限继续只由 `app-session.js` 掌管。
- 新增实验需同步 `CONFIG.experiments`、`AstraExperimentRegistry`、`data-module` DOM 和对应实现文件；脚本/init/cleanup 状态只在注册表登记，`ModuleSelector` 是运行入口，Router 不再维护实验清理表。
- cleanup 边界保持 65 项 `legacy-callback / verified:false`、23 项 `validated-callback / verified:true`、0 项 `missing`。`AstraExperimentRegistry.cleanupModule(subject, id)` 只执行精确 `verified:true` owner，并返回冻结报告 `unknown`、`unverified`、`owner-unavailable`、`cleaned` 或 `failed`；65 项 legacy 绝不执行模块级 callback。`openModule()` 的 A→B 与 `closeModule()` 的 B→画廊会先关闭学科 Zoom、清理当前已验证实验 owner，再释放当前学习证据 owner；任一步失败都在 DOM、hash 和 active state 变化前中止，且证据 controller 只在 owner cleanup 确认成功后销毁。整页离开仅在 `cleanupPage()` 至少执行一个已加载 owner 且 `failed === 0` 时释放证据 controller；未加载 legacy owner 会令 `executed < attempted`，不应误判为失败。成功 cleanup 删除初始化标记以允许重新 init；legacy 保留初始化标记。transition generation 会取消或失效旧资源加载、init 重试、resize、焦点和相关推荐 timer，dirty legacy 不得在同页重复 init；整页离开继续通过 `skipExperimentCleanup` 防止双执行。
- `index.html`、`APP_SHELL` 与星系 HTTP fallback 不得静态包含三角色 CSS/JS。`AstraPageRegistry` 维护页面角色与样式/脚本矩阵，`app-session.js` 仅在 `/api/users/me` 成功后加载允许样式；Router 只在角色守卫通过后加载页面脚本。三端资源由 Service Worker 使用 `cache: no-store` 的 network-only 分支处理，退出、运行中 401 与跨角色重新认证必须清理角色样式/CacheStorage 并整页重载。
