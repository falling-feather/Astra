## 1. 系统全貌

星序由主站 SPA、代码空间子站、FastAPI 业务后端、数据库和静态交付服务组成。浏览器先通过 `/api/users/me` 确认服务端 Session，再启动 Router；学生、教师和管理员的导航、section 与受保护脚本按权威角色裁剪。

```text
主站 index.html / shared / pages ──┐
代码空间 codevis ──────────────────┼──> 浏览器 + HttpOnly Cookie
                                   │             │
                                   │             ▼
Node/C++ 静态服务 <────────────────┘      FastAPI backend
                                                  │
                                SQLite 本地展示 / MySQL 后置发布
```

`main@V7.5.11` 是公开稳定线；`主开发` 当前集成线已包含 FE-012 的共享学习证据、发布态 / authority、44px、移动浮层、预测确认、移动端力学、Escape、精确单元处置与四项教学闭环返修。V7.7.29 曾完成既定 A03a 矩阵；其后同一产品树的补充移动→桌面保持打开探针稳定复现 Zoom P3：最终 943px host 仍使用过渡期 863px backing store 并被自动放大。V7.7.30 候选复用 PhysicsSim 既有 ResizeObserver，在同一 Canvas 由 Zoom 持有时把原父容器稳定尺寸交给窄校准入口，继续只由 `PhysicsSim.resizeForZoom()` 写 CSS、backing store、DPR、`W/H` 与即时 render；自动 base scale 上限为 1，保留下缩和用户主动 pinch，且不新增 Observer、RAF、全局监听或第二 Canvas writer。该候选仍须独立复审与真实浏览器续验，不能提前写成完整 FE-012 / A03a 已关闭。当前作品以课程作业 / 设计大赛的本地展示版为交付目标：优先完成代表课程互动、三角色协同、9001 一键启动和 SQLite 数据对账。真实 MySQL、隔离 runner、域名、公网 R6、压力测试、真实课堂试点和 AI 能力保留为后置工程，不阻塞 V8.0 展示版，也不得被文案外推为已上线。

V7.8.5 的教师端当前实现已收束为三个主入口，并接入显式班级 / 课程范围、学生 × 分块进度、逐学生安全证据与追加式纠错、发布预览确认、评分权威回读和正式 runner 状态边界；其独立 QA 与版本完成状态仍以 `02/03` 为准。

V7.8.7 的教师证据 owner 会分别记录当前 `base + class + course` 范围和最近一次实际刷新所消费的课程挂接布尔值。同一范围内挂接由 false 变 true 时，既有单 timer 只恢复一组 progress + aggregate 请求；由 true 变 false 时不发新请求，并同步中止在途请求、关闭对话框、清空表格 / 移动详情、证据事实、选择、纠错、反馈和加载状态。重复收到相同挂接状态不会形成请求风暴；独立运行时验收与版本完成状态仍以 `02/03` 为准。

### 2.1 权威学习证据合同

新合同统一挂在 `/api/learning-evidence`，只接受服务端 Session/Bearer 既有认证边界：

| 能力 | 接口 | 权限与结果 |
| --- | --- | --- |
| 完成规则 | `POST/GET /rules`、`GET /rules/activation`、`POST /rules/{rule_id}/activate` | owner、`assessment_editor` 或 admin 可创建不可变版本；draft 规则可预置本课程未来活动，但激活时 activity scope 必须与全部当前 published 单元精确相等，并使用 course edit scope、`expected_revision` CAS 和可选班级 `expected_plan_version` 绑定；activation state 返回当前 revision、active rule 与各 active class 的有效 pin；后续纯发布调整继承最近一次绑定，直至新计划版本追加新绑定 |
| 学习事实 | `POST /events`、`POST /events/batch` | 学生只能追加 v1 `started/predicted/attempted/corrected/explained`；服务端持久化 `event_schema_version=1`，客户端不能指定；单项结果为 `accepted/duplicate/rejected/conflict` |
| 教师纠错 | `POST /events/{event_id}/corrections` | 本班教师或 admin 追加独立行政纠错事实；新纠错与学生/受信写入共用发布锁，目标当前 effective access 必须为 open；资源后来 hidden/locked/archived 后，本人精确旧键仍只返回最小 duplicate 回执；原事件不更新、不删除，同一目标只接受一个行政纠错 |
| 教师逐学生证据发现 | `GET /classes/{class_id}/courses/{course_id}/events?subject_user_id=&activity_key=&event_type=&limit=&offset=` | 本班 active teacher 或全局 admin 在精确 `class + course + subject` 范围内读取稳定倒序分页，`limit` 为 1—100、`offset` 为 0—100000；学生、外班教师、未挂班与跨校范围 fail closed。响应保留 learner / trusted-assessment 外层事实、内部纠错用 `event_id` 与纠错关联 ID，并把 `activity_key + event_schema_version + event_type + exact leaf path` 交给纯投影模块。schema v1 当前仅 `physics.mechanics` 与现有浅层 `control-flow.loop-boundary` 可产生最多 12 个固定中文 facts；其余四门、其他 activity、未知 schema/event 固定为空 facts 且 `truncated=true`。源码、开放文本、原始枚举、source/ref/revision/hash/token、未知 nested raw 与原始 evidence JSON 均不返回 |
| 学生恢复 | `GET /me/recovery?class_id=&course_id=` | 返回当前班级发布计划所绑定规则版本下的可见活动投影；只有 effective access 为 `open` 的最后位置及活动项才返回可执行续学游标，locked 顶层 `resume=null` 且活动 `resume_cursor={}`，hidden 活动与游标都不回读 |
| 教师聚合与修复 | `GET /classes/{class_id}/courses/{course_id}/aggregate`、`POST .../rebuild` | 本班教师或 admin 读取当前 bound rule 明确定义的稳定 activity scope（hidden 对教师仍可见，非规则或未发布单元不进入 active 聚合），或从 append-only 事实重建活动/续学投影 |

维护不变量：

- `client_event_id` 与规范化请求 SHA-256 共同实现精确幂等；相同 actor/subject 与相同载荷返回不含课程内容元数据的最小旧回执，换 actor/subject 返回 `403`，同键异载荷返回 `409`。
- 所有学习证据写命令 DTO 都拒绝未知字段。外部 `client_event_id` 必须以 ASCII 字母或数字开头；服务端规则派生使用客户端不能构造的 `@rule:` 保留命名空间，命中既有内部键时仍逐项核对 producer、request hash、subject/scope、rule/outcome 与 source IDs，不一致固定 `409`。
- `course_release_write_gate` 承载学生、OJ、提交、legacy event 和学习证据共用写门禁；实际锁序为 `school → course → class → membership/permission → course-class → unit → plan/assignment policy → binding/rule → ledger/projection`，release-plan PATCH 使用共享的 `school → class → course-class → plan` 子序列。两者先在 school 行序列化，且学生门禁在成员重验后先锁 course-class、再锁 unit/plan。hidden、locked、archived、未来时间、旧规则或班级/课程/活动不匹配均拒绝。事件、规则派生结果和投影在同一事务提交，提交成功后恢复/聚合读取立即可见。
- `completed/transferred` 只由规则服务或内部受信评测入口生成；`transferred` 只表示真实教学迁移任务。教师行政纠错使用 `administrative_correction`，不与学生的 `corrected` 混用。

### 2.2 管理员课程状态治理

`PATCH /api/courses/{course_id}/status` 仅允许全局管理员调用，请求体严格为 `expected_status + status + reason`，未知字段固定 `422`。状态转换只允许 `draft → published/archived`、`published → draft/archived`、`archived → draft`；stale、no-op 和 `archived → published` 均返回 `409`。

DTO 与 endpoint 分别由 `schemas/course_status.py`、`api/endpoints/course_status.py` 持有，并由 `api/router.py` 在 `/courses` 注册；冻结 `api/endpoints/courses.py`、`schemas/course.py` 不增长。写入顺序固定为 `ADMIN_AUTHORITY_LOCK → school → course → lock_active_admin`，锁后重新读取并确认 actor 仍是 active global admin，再执行状态 compare-and-swap。当前单进程 SQLite 展示路径使用同领域事务锁串行化竞争写入，并把残余 `database locked/busy` 归一为 `409`，所以同一 `expected_status` 的并发请求只能产生一条成功审计。成功响应返回提交后的 `CourseRead`，以及 active 挂接班级、课程单元和作业计数；审计动作固定为 `course.status.patch`，快照保存 `before/after/reason/impact`。接口不接受标题、摘要、owner 或其他课程字段，且不新增迁移。

UI-003 / V7.9.4 当前实现不改变上述 BE-007 合同，只补管理员消费面：

- `pages/admin/admin.js` 保持窄 orchestrator 与不超过 2485 行；仅在本页再次读取 `/api/users/me` 并确认 `role=admin` 后，才动态加载 `admin-course-governance.js` 和 `admin-secondary-governance.js`。匿名、student、teacher 不预热或缓存两个 owner；任一 owner 脚本加载失败会清除本批次两个节点、全部 load/error 监听和共享 Promise，后续显式刷新创建全新节点重试，并发调用仍共享同一有效批次。

### 2.3 学生单元访问处置

`GET /api/courses/{course_id}/unit-access?class_id=&activity_key=` 只允许 student 调用。服务先按既有学校、成员关系、挂班和 published 课程语义确认学生对精确 `class + course` 有权，再以最长 120 字符、规范小写分段格式的 `activity_key` 做 exact match，并复用 `resolve_student_course_class`、`get_plan_for_unit` 与 `effective_unit_access` 计算当前发布态。

已授权范围内固定返回两个字段：open 为 `{"available":true,"error_code":null}`，hidden / locked / missing 分别返回 `activity_hidden`、`activity_locked`、`course_unit_missing` 且 HTTP 状态均为 `200`。响应不返回单元 ID、标题、正文、slug、发布计划、锁定原因、其他 activity key 或目录；未登录、非学生、未入班、跨班、跨校、draft / archived 课程和 inactive school 继续沿用 `401/403`，非法 `class_id` 或 activity key 为 `422`。同一课程内 activity key 多匹配、目标 plan 缺失、目标关联不一致或未知发布态固定失败关闭为 `409`；无关 plan 漂移不阻断目标读取。正式 schema 的唯一约束阻止正常写入产生重复 plan，运行时不承诺识别绕过约束注入的重复 plan 行。

该能力由独立 schema / endpoint / service 持有，router 只在 `/courses` 注册；冻结 `api/endpoints/courses.py`、`schemas/course.py`、模型与迁移均不变化，也不产生写事务、锁或审计。现有学生 units 列表仍隐藏 hidden 单元；该处置接口只为已知 deep-link 分类提供最小结果，不扩张为目录发现。V7.7.22 前端集成只在 `/units` 精确零匹配后消费该结果，并以严格 DTO、同一取消信号和固定诊断失败关闭；仍需真实浏览器验收，不能把代码 / 合同通过写成 deep-link 产品闭环已经交付。
